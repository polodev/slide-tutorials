# Slide Tutorials — agent guide

Byte-size **Bangla** slide tutorials (English technical terms), published on GitHub Pages:
https://polodev.github.io/slide-tutorials/ (repo `polodev/slide-tutorials`, branch `main`, served from `/`).

## Audience and voice

- Learner: a junior **PHP/Laravel** developer in Bangladesh. Every new idea gets a PHP/Laravel bridge
  (`php_note(...)`, a runnable `code(..., "php")` comparison, or a Laravel snippet).
- Bangla prose, English technical words (`function`, `Deployment`, `index`). No romanized Bangla.
- Examples use one running story: the "Rahim Mobile" phone shop (products, branches Mirpur/Uttara/Gulshan,
  invoices INV-10xx, Taka amounts). First program in every course prints `Hello, World!`.
- One slide = one small idea: 1–3 short points + one short code block + real output. Prefer more slides with
  less text. Add `task(...)` (exercise) or `quiz(...)` where useful.

## Golden rule: nothing on a slide is invented

Every runnable block is executed at build time and the **real** output, compiler error, HTTP response, query
result, screenshot or linter result is rendered. If a block fails, fix the lesson — never hand-write output.
`shell(src, out=...)` (hand-written sample output) is only for things that cannot run here (cloud, certbot,
systemctl, registry push); keep those few.

## Layout

```
index.html                 hub (generated by build.py)
build.py                   builds every series + hub  (python3 build.py, or --hub for the hub only)
tutorial-kit/kit.py        the engine (Course, blocks, runners, HTML/CSS/JS)
tutorial-kit/eloquent/     composer project (illuminate/database) for Laravel snippets; vendor/ ignored
tutorial-kit/eloquent_bootstrap.php
tutorial-kit/fonts/        Hind Siliguri (Flutter screenshots)
tutorial-kit/fetch_devops_bins.py   downloads DevOps binaries into tutorial-kit/.cache/bin (nothing system-wide)
tutorial-kit/.cache/       git-ignored: results cache, cargo target, flutter project, pgdata, shell sandboxes
<series>/build.py          builds the series' courses + its index.html (build_home)
<series>/<course>/build.py one course → index.html + course.json
```

Series: `rust-tutorial`, `go-tutorial`, `dart-tutorial` (incl. `flutter`), `mysql-tutorial`,
`postgresql-tutorial`, `devops-tutorial` (in progress), `accounts-101` (own older builder, not the kit).

## Writing a course

```python
c = Course(slug="go-101", title="…", subtitle="…", series="Go 101", folder=Path(__file__).parent,
           next_course=("../go-102/index.html", "Go 102 — …"))
c.cover(title, lead, learn=[...], need="…")
c.section("শুরু")
c.lesson("শিরোনাম", say("…"), points("…", "…"), php_note("…"), code(SRC, "go"), task("…"))
c.finish(title, lead, recap=[...])
c.build()
```

Text blocks: `say`, `points`, `tip`, `warn`, `php_note`, `task`, `quiz`, `table`, `steps`. Code blocks go to the
right column automatically.

### Code runners (`code(src, lang, **opts)`)

| lang / option | What happens |
|---|---|
| `rust` | rustc --edition 2024; `err="E0382"` expects that compile error; `panic=True`; `stdin=`; `test=True` (rustc --test) |
| `rust` + `deps={...}` | Cargo project with crates; `requests=[curl ...]` starts the server and records responses |
| `go` | `go run` (gofmt applied to the shown source); `err=`, `panic=`, `stdin=`; `test=True, app=SRC` → `go test -v`; `deps=[module]`; `requests=` for servers |
| `dart` | `dart run`; `deps={"http": "^1.2.0"}`; `test=True` → dart test |
| `dart` + `flutter=True` | analyzed with --fatal-infos, then a **real screenshot** via golden test (`actions=[tester code]` taps/types first); `test=True, app=SRC` runs a widget test. Apps must define `class App` with a const constructor. |
| `php` | php CLI; `eloquent=True` runs against the course database with the course `models=` file and prints SQL via `queries(fn)` |
| `mysql` / `postgresql` | runs in one fresh database per course (`Course(sql_engine=...)`), blocks build on each other; `err="..."` for intentional errors |
| `term(src)` | `$ cmd` lines run in the course's shell sandbox (`Course(shell=True)`), optionally inside a container (`c.shell_container`) |
| `save=True, file=...` | writes the block into the shell sandbox; `validate="dockerfile"/"kube"/"actions"/"prometheus"/"promrules"` lints it |
| `hidden=True` | setup file saved but not shown |
| `run=False` | display only (configs, folder trees) |

Servers in lessons listen on `:3000` on the slide; the kit rewrites to a private test port (3787) because 3000
is used by another app on this machine. Postgres runs as a private throwaway cluster on port 5544.

### Rules learned the hard way

- Read each new course's outputs after building (`re.findall('<pre>(.*?)</pre>', html)`) — check the text matches
  what the slide claims (e.g. N+1 showed 8 queries, not 11; full-text precedence; MySQL skip-scan).
- No compiler warnings in examples (learners copy them). Make examples deterministic (no random order unless the
  slide is about it; avoid printing current time).
- Ligatures are disabled in code (`<=` must look like `<=`).
- Mobile: decks are fixed to the viewport; vertical drag scrolls a slide, horizontal swipe changes slide; code
  wraps on small screens. Test with Playwright mobile emulation (390×844, isMobile, hasTouch) when touching CSS/JS.
- In one Python process all series build together — give shared helper modules unique names
  (e.g. `pg_shop_schema` vs `shop_schema`).
- Never write outside the sandbox from shell lessons; absolute `file=` paths go only into the container.

## Build, check, publish

```bash
python3 build.py                       # everything (cached; unchanged blocks are not re-run)
python3 go-tutorial/build.py           # one series
python3 go-tutorial/go-101/build.py    # one course
```

Requirements: python3 + pygments, rustc/cargo, go, dart/flutter, php (Herd) + `composer install` in
`tutorial-kit/eloquent`, local MySQL 8 (`mysql -uroot`), PostgreSQL 16 binaries (Homebrew keg; kit starts its own
cluster), and for DevOps `python3 tutorial-kit/fetch_devops_bins.py` (Colima/Docker/kind/kubectl/helm/...).

Commit and push after each finished series. **Commits must not mention Claude/AI and must not add
Co-Authored-By trailers** (author: the user's git identity). Pages deploys automatically from `main`.

## Adding a new series

1. `newseries/<course>/build.py` per course, `newseries/build.py` with `build_home(...)` and the COURSES list.
2. Add the folder to `SERIES` and an entry to `tutorials()` in the root `build.py`, and a row in `README.md`.
3. `python3 newseries/build.py && python3 build.py --hub`, check desktop + mobile, commit, push.
