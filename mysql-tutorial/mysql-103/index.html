Index, Transaction ও Window function

Query লিখতে পারেন। এবার শিখব কীভাবে ৫০ হাজার row-এও query মুহূর্তে চলে, টাকা-স্টকের হিসাব কখনো আধাআধি না হয়, আর এক query-তে র‍্যাংকিং বা চলমান যোগফল।

  • Index কী, EXPLAIN পড়া
  • Composite index আর leftmost নিয়ম
  • কোন query index ব্যবহার করতে পারে না
  • Transaction: COMMIT, ROLLBACK
  • Window function: ROW_NUMBER, RANK, LAG
  • CTE আর recursive CTE
  • JSON column আর generated column
  • CHECK, trigger, full-text, user permission

আগে জানা দরকার: MySQL 102 (JOIN, GROUP BY, subquery)।

CREATE TABLE branches (

CREATE TABLE customers (
    id       INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name     VARCHAR(100) NOT NULL,
    phone    VARCHAR(15)  NOT NULL UNIQUE,
    district VARCHAR(50)
);

CREATE TABLE categories (
    id   INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL
);

CREATE TABLE products (
    id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    category_id INT UNSIGNED NOT NULL,
    name        VARCHAR(100) NOT NULL,
    brand       VARCHAR(50)  NOT NULL,
    cost        DECIMAL(10,2) NOT NULL,
    price       DECIMAL(10,2) NOT NULL,
    stock       INT UNSIGNED NOT NULL DEFAULT 0,
    FOREIGN KEY (category_id) REFERENCES categories (id)

CREATE TABLE employees (
    id        INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    branch_id INT UNSIGNED NOT NULL,
    name      VARCHAR(100) NOT NULL,
    FOREIGN KEY (branch_id) REFERENCES branches (id)

CREATE TABLE sales (
    id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    invoice_no  VARCHAR(20) NOT NULL UNIQUE,
    branch_id   INT UNSIGNED NOT NULL,
    employee_id INT UNSIGNED NOT NULL,
    customer_id INT UNSIGNED NULL,            -- walk-in হলে NULL
    sold_at     DATETIME NOT NULL,
    total       DECIMAL(10,2) NOT NULL,
    FOREIGN KEY (branch_id)   REFERENCES branches (id),
    FOREIGN KEY (employee_id) REFERENCES employees (id),
    FOREIGN KEY (customer_id) REFERENCES customers (id)
);

CREATE TABLE sale_items (
    id         INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    sale_id    INT UNSIGNED NOT NULL,
    product_id INT UNSIGNED NOT NULL,
    qty        INT UNSIGNED NOT NULL,
    unit_price DECIMAL(10,2) NOT NULL,
    FOREIGN KEY (sale_id)    REFERENCES sales (id) ON DELETE CASCADE,
    FOREIGN KEY (product_id) REFERENCES products (id)
);

MySQL — ৫০,০০০ order
CREATE TABLE orders (
    id             INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    branch_id      INT UNSIGNED NOT NULL,
    customer_phone VARCHAR(15)  NOT NULL,
    status         ENUM('paid', 'due', 'cancelled') NOT NULL,
    total          DECIMAL(10,2) NOT NULL,
    created_at     DATETIME NOT NULL
);

SET SESSION cte_max_recursion_depth = 100000;

INSERT INTO orders (branch_id, customer_phone, status, total, created_at)
WITH RECURSIVE seq (n) AS (
    SELECT 1 UNION ALL SELECT n + 1 FROM seq WHERE n < 50000
)
SELECT n % 3 + 1,
       CONCAT('017', LPAD(n % 20000, 8, '0')),
       ELT(n % 3 + 1, 'paid', 'due', 'cancelled'),
       (n % 500) * 100 + 500,
       '2026-01-01' + INTERVAL (n % 290) DAY + INTERVAL (n % 86400) SECOND
FROM seq;

ANALYZE TABLE orders;

Index ছাড়া: পুরো table পড়া

একটা ফোন নম্বরের order খুঁজতে MySQL-কে ৫০,০০০ row-ই পড়তে হয় (table scan)। EXPLAIN দেখায় MySQL কীভাবে query চালাবে।

💡 Table scan আর rows= সংখ্যাটা দেখুন — প্রায় সব row।
MySQL
EXPLAIN FORMAT=TREE
SELECT * FROM orders WHERE customer_phone = '01700001234';
ফলাফল
-> Filter: (orders.customer_phone = '01700001234')  (cost=5075 rows=5018)
    -> Table scan on orders  (cost=5075 rows=50184)

Composite index আর leftmost নিয়ম

দুই column একসাথে: (branch_id, created_at)। Index সাজানো থাকে আগে branch, তারপর তারিখ ধরে — ফোনবুক যেমন আগে পদবি, তারপর নাম। তাই branch + তারিখ দিয়ে খোঁজা সবচেয়ে দ্রুত।

💡 দুটো cost তুলনা করুন: branch + তারিখে ~৮২, শুধু তারিখে ~১৪১০। শুধু তারিখ দিলে MySQL 8 "skip scan" দিয়ে প্রতিটি branch আলাদা করে ঘোরে — চলে, কিন্তু অনেক বেশি খরচে। প্রায়ই শুধু তারিখে খুঁজলে আলাদা (created_at) index দিন।

CREATE INDEX orders_branch_created_index ON orders (branch_id, created_at);

Index-এর খরচ

  • প্রতিটি index disk-এ জায়গা নেয়
  • INSERT/UPDATE-এ প্রতিটি index-ও আপডেট হয় — লেখা ধীর হয়
  • যে column দিয়ে প্রায়ই WHERE, JOIN বা ORDER BY করেন, শুধু সেগুলোতে index
  • Foreign key column-এ MySQL নিজেই index বানায়
❓ status column-এ (মাত্র ৩টা আলাদা মান) একা index দেওয়া কি ভালো?

সাধারণত না — এক-তৃতীয়াংশ row মিলে যায়, table scan-ই প্রায় সমান দ্রুত। অন্য column-এর সাথে composite index হলে কাজে লাগতে পারে।

পাঠ ৮

Transaction কেন?

একটা বিক্রিতে তিনটা কাজ: sale লেখা, item লেখা, স্টক কমানো। মাঝখানে ভুল হলে? স্টক কমে গেল কিন্তু বিক্রি লেখা হলো না — হিসাব নষ্ট।

  • Transaction: কয়েকটা কাজ একসাথে — হয় সব হবে, নয়তো একটাও না
  • START TRANSACTION → কাজ → COMMIT (পাকা করো) অথবা ROLLBACK (সব বাতিল)
  • InnoDB engine (MySQL-এর ডিফল্ট) transaction সমর্থন করে
PHP/Laravel-এ যেমন Laravel-এর DB::transaction(function () { ... }); ভিতরে এটাই করে: exception হলে ROLLBACK, নইলে COMMIT।

মাঝপথে error হলে

স্টক UNSIGNED — ০-এর নিচে যেতে পারে না। দ্বিতীয় UPDATE ব্যর্থ হয়, client থেমে যায়, আর commit না হওয়া transaction নিজে থেকেই বাতিল (rollback) হয়।

Charger-এর স্টকও কমেনি (৩০ আছে) — কারণ দুটো UPDATE একই transaction-এ ছিল।

একই স্টক দুইজন বিক্রি করলে: FOR UPDATE

দুই কাউন্টার একসাথে শেষ iPhone বিক্রি করছে — দুজনেই দেখল stock = 1। SELECT ... FOR UPDATE row-টা তালাবদ্ধ করে; দ্বিতীয়জন অপেক্ষা করে, প্রথমজনের COMMIT-এর পর নতুন মান দেখে।

💡 Transaction ছোট রাখুন — ভিতরে API call বা ধীর কাজ করবেন না, নইলে অন্যরা তালার জন্য অপেক্ষা করবে (lock wait, deadlock)।
MySQL
START TRANSACTION;
SELECT id, name, stock FROM products WHERE id = 4 FOR UPDATE;
-- stock > 0 হলে বিক্রি; অন্য transaction এই row-এর জন্য এখন অপেক্ষা করবে
UPDATE products SET stock = stock - 1 WHERE id = 4;
COMMIT;

DB::transaction(function () use ($productId) {
    $product = Product::lockForUpdate()->findOrFail($productId);

    $product->decrement('stock');
});

ROW_NUMBER: র‍্যাংকিং

Window function GROUP BY-এর মতো row একত্র করে না — প্রতিটি row রেখে পাশে হিসাব যোগ করে। OVER (...) বলে কোন "জানালা" ধরে।

প্রতি শাখার সেরা invoice

Window function সরাসরি WHERE-এ দেওয়া যায় না — আগে CTE (WITH)-এ হিসাব, তারপর বাইরে filter।

PHP/Laravel-এ যেমন "প্রতিটি customer-এর সর্বশেষ order" — Laravel-এ latestOfMany() relationship ভিতরে এরকম query বানায়।
MySQL
WITH ranked AS (
    SELECT branch_id, invoice_no, total,
           ROW_NUMBER() OVER (PARTITION BY branch_id ORDER BY total DESC) AS rn
    FROM sales
)
SELECT b.name AS branch, r.invoice_no, r.total
FROM ranked r
JOIN branches b ON b.id = r.branch_id
WHERE r.rn = 1;

RANK বনাম DENSE_RANK

  • ROW_NUMBER — সমান হলেও আলাদা নম্বর
  • RANK — সমানরা একই নম্বর, তারপর ফাঁক (১,১,৩)
  • DENSE_RANK — সমানরা একই, ফাঁক নেই (১,১,২)
MySQL
SELECT p.name, SUM(si.qty) AS sold,
       ROW_NUMBER() OVER (ORDER BY SUM(si.qty) DESC) AS row_no,
       RANK()       OVER (ORDER BY SUM(si.qty) DESC) AS rnk,
       DENSE_RANK() OVER (ORDER BY SUM(si.qty) DESC) AS dense
FROM sale_items si
JOIN products p ON p.id = si.product_id
GROUP BY p.id, p.name
LIMIT 6;

চলমান যোগফল আর আগের দিনের তুলনা

  • SUM() OVER (ORDER BY day) — শুরু থেকে আজ পর্যন্ত যোগফল
  • LAG(revenue) — আগের row-এর মান; LEAD পরের
MySQL
WITH daily AS (
    SELECT DATE(sold_at) AS day, SUM(total) AS revenue
    FROM sales
    GROUP BY DATE(sold_at)
)
SELECT day,
       revenue,
       SUM(revenue) OVER (ORDER BY day)   AS running_total,
       revenue - LAG(revenue) OVER (ORDER BY day) AS vs_yesterday
FROM daily;

Recursive CTE: খালি দিনও দেখানো

যে দিনে বিক্রি নেই, GROUP BY সেই দিন দেখায় না — chart-এ ফাঁক পড়ে। Recursive CTE দিয়ে সব তারিখ বানিয়ে LEFT JOIN করি।

MySQL
WITH RECURSIVE days (day) AS (
    SELECT DATE('2026-10-14')
    UNION ALL
    SELECT day + INTERVAL 1 DAY FROM days WHERE day < '2026-10-21'
)
SELECT d.day,
       COUNT(s.id)             AS invoices,
       IFNULL(SUM(s.total), 0) AS revenue
FROM days d
LEFT JOIN sales s ON DATE(s.sold_at) = d.day
GROUP BY d.day
ORDER BY d.day;

JSON column

সব ফোনের spec এক রকম না — কিছু field ঐচ্ছিক। JSON column-এ নমনীয় data রাখা যায়, আবার query-ও করা যায়।

MySQL
ALTER TABLE products ADD COLUMN specs JSON NULL;

UPDATE products SET specs = '{"ram": 8, "storage": 256, "colors": ["Black", "Green"]}' WHERE id = 2;
UPDATE products SET specs = '{"ram": 4, "storage": 128, "colors": ["Blue"]}'           WHERE id = 3;
UPDATE products SET specs = '{"ram": 4, "storage": 64,  "colors": ["Black"]}'          WHERE id = 4;

SELECT name,
       specs->>'$.ram'     AS ram_gb,
       specs->>'$.storage' AS storage_gb,
       JSON_LENGTH(specs->'$.colors') AS colors
FROM products
WHERE specs->>'$.ram' >= 4
ORDER BY name;

Trigger: স্টক বদলালে log

Trigger হলো এমন কোড যা table-এ কিছু হলে database নিজেই চালায়। এখানে স্টক বদলালেই একটা log row।

PHP/Laravel-এ যেমন Laravel-এ সাধারণত Model event/Observer (updated()) দিয়ে এই কাজ করা হয়। Trigger সব জায়গা থেকে আসা UPDATE ধরে — এমনকি হাতে চালানো SQL-ও।
MySQL
CREATE TABLE stock_logs (
    id         INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    product_id INT UNSIGNED NOT NULL,
    old_stock  INT UNSIGNED NOT NULL,
    new_stock  INT UNSIGNED NOT NULL,
    changed_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TRIGGER products_stock_log AFTER UPDATE ON products
FOR EACH ROW
INSERT INTO stock_logs (product_id, old_stock, new_stock)
SELECT NEW.id, OLD.stock, NEW.stock FROM DUAL WHERE OLD.stock <> NEW.stock;

UPDATE products SET stock = stock + 10 WHERE id = 6;
UPDATE products SET price = price WHERE id = 7;    -- স্টক বদলায়নি: log হবে না
SELECT product_id, old_stock, new_stock FROM stock_logs;

Full-text search

LIKE '%word%' বড় table-এ ধীর। FULLTEXT index আর MATCH ... AGAINST শব্দ ধরে খোঁজে, প্রাসঙ্গিকতা অনুযায়ী সাজায়।

💡 বড় app-এ Laravel Scout + Meilisearch/Typesense ভালো — typo সহ্য করে, বাংলাও খোঁজে।
MySQL
ALTER TABLE products ADD FULLTEXT INDEX products_name_fulltext (name, brand);

SELECT name, brand
FROM products
WHERE MATCH (name, brand) AGAINST ('redmi xiaomi' IN NATURAL LANGUAGE MODE);

ধীর query খুঁজে বের করা

Slow query log চালু করলে নির্দিষ্ট সময়ের বেশি লাগা query file-এ লেখা হয়। তারপর সেগুলো EXPLAIN দিয়ে দেখুন।

সমস্যাসমাধান
WHERE/JOIN column-এ index নেইIndex যোগ করুন (EXPLAIN-এ table scan)
SELECT * বড় TEXT/JSON সহদরকারি column বাছুন
Column-এ function (DATE(), LOWER())Range শর্ত বা generated column
অনেক বড় OFFSET (পাতা ১০০০০)Keyset/cursor pagination (MySQL for Laravel)
Loop-এ query (N+1)JOIN বা eager loading
PHP/Laravel-এ যেমন Laravel Telescope / Debugbar প্রতিটি request-এর query আর সময় দেখায় — ধীর query ধরার সহজ উপায়।
