পাঠ ২

Table গুলো: Rahim Mobile

ছয়টা table। FOREIGN KEY লাইনগুলো বলছে কোন column অন্য কোন table-এর id-কে নির্দেশ করে।

সম্পর্কধরনEloquent
branch → employeesএক শাখায় অনেক কর্মচারীhasMany
sale → customerপ্রতিটি বিক্রি একজন customer-এর (বা walk-in)belongsTo
sale → sale_items → productএক বিক্রিতে অনেক product, এক product অনেক বিক্রিতেbelongsToMany (pivot)
MySQL — schema
CREATE TABLE branches (
    id   INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL
);

CREATE TABLE customers (
    id       INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name     VARCHAR(100) NOT NULL,
    phone    VARCHAR(15)  NOT NULL UNIQUE,
    district VARCHAR(50)
);

CREATE TABLE categories (
    id   INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL
);

CREATE TABLE products (
    id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    category_id INT UNSIGNED NOT NULL,
    name        VARCHAR(100) NOT NULL,
    brand       VARCHAR(50)  NOT NULL,
    cost        DECIMAL(10,2) NOT NULL,
    price       DECIMAL(10,2) NOT NULL,
    stock       INT UNSIGNED NOT NULL DEFAULT 0,
    FOREIGN KEY (category_id) REFERENCES categories (id)
);

CREATE TABLE employees (
    id        INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    branch_id INT UNSIGNED NOT NULL,
    name      VARCHAR(100) NOT NULL,
    FOREIGN KEY (branch_id) REFERENCES branches (id)
);

CREATE TABLE sales (
    id          INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    invoice_no  VARCHAR(20) NOT NULL UNIQUE,
    branch_id   INT UNSIGNED NOT NULL,
    employee_id INT UNSIGNED NOT NULL,
    customer_id INT UNSIGNED NULL,            -- walk-in হলে NULL
    sold_at     DATETIME NOT NULL,
    total       DECIMAL(10,2) NOT NULL,
    FOREIGN KEY (branch_id)   REFERENCES branches (id),
    FOREIGN KEY (employee_id) REFERENCES employees (id),
    FOREIGN KEY (customer_id) REFERENCES customers (id)
);

CREATE TABLE sale_items (
    id         INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    sale_id    INT UNSIGNED NOT NULL,
    product_id INT UNSIGNED NOT NULL,
    qty        INT UNSIGNED NOT NULL,
    unit_price DECIMAL(10,2) NOT NULL,
    FOREIGN KEY (sale_id)    REFERENCES sales (id) ON DELETE CASCADE,
    FOREIGN KEY (product_id) REFERENCES products (id)
);

COUNT, SUM, AVG, MIN, MAX

Aggregate function অনেক row থেকে একটা মান বানায়।

MySQL
SELECT COUNT(*)            AS invoices,
       SUM(total)          AS revenue,
       ROUND(AVG(total))   AS avg_invoice,
       MIN(total)          AS smallest,
       MAX(total)          AS biggest
FROM sales;
ফলাফল

| invoices | revenue   | avg_invoice | smallest | biggest  |

|       10 | 159850.00 |       15985 |  1300.00 | 48000.00 |
+----------+-----------+-------------+----------+----------+
1 row in set
Laravel-এ
Sale::count();  Sale::sum('total');  Sale::avg('total');  Sale::max('total');
পাঠ ৫

GROUP BY: শাখা ধরে

GROUP BY branch_id — প্রতিটি শাখার row আলাদা দলে, তারপর প্রতিটি দলের হিসাব।

⚠️ SELECT-এ যে column থাকবে তা হয় GROUP BY-এ থাকবে, নয়তো aggregate-এর ভিতরে। নইলে MySQL error দেয় (ONLY_FULL_GROUP_BY)।
MySQL
SELECT branch_id,
       COUNT(*)   AS invoices,
       SUM(total) AS revenue
FROM sales
GROUP BY branch_id
ORDER BY revenue DESC;
ফলাফল
+-----------+----------+----------+
| branch_id | invoices | revenue  |
+-----------+----------+----------+
|         3 |        2 | 69650.00 |
|         1 |        5 | 60850.00 |
|         2 |        3 | 29350.00 |
+-----------+----------+----------+
3 rows in set
Laravel-এ
Sale::selectRaw('branch_id, COUNT(*) AS invoices, SUM(total) AS revenue')
    ->groupBy('branch_id')->orderByDesc('revenue')->get();

HAVING: দলের উপর শর্ত

WHERE row বাছাই করে দল বানানোর আগে। HAVING দল বানানোর পরে — aggregate-এর উপর শর্ত।

❓ "৫০ হাজারের বেশি বিক্রি করেছে এমন শাখা" — WHERE না HAVING?

HAVING SUM(total) > 50000 — কারণ শর্তটা যোগফলের উপর।

MySQL
SELECT customer_id,
       COUNT(*)   AS visits,
       SUM(total) AS spent
FROM sales
WHERE customer_id IS NOT NULL
GROUP BY customer_id
HAVING COUNT(*) >= 2;

INNER JOIN: দুই table জোড়া

JOIN ... ON দিয়ে বলি কোন column মিলিয়ে জোড়া হবে। এখন branch_id-এর বদলে শাখার নাম দেখাতে পারি।

💡 sales AS s — ছোট নাম (alias) দিলে লম্বা query পড়তে সহজ।
MySQL
SELECT s.invoice_no, b.name AS branch, s.total
FROM sales AS s
JOIN branches AS b ON b.id = s.branch_id
ORDER BY s.sold_at
LIMIT 5;

Sale::join('branches', 'branches.id', '=', 'sales.branch_id')

    ->groupBy('branches.id', 'branches.name')
    ->orderByDesc('revenue')->get();

অনেক table: পুরো invoice

SELECT s.invoice_no,
       c.name  AS customer,
       e.name  AS sold_by,
       p.name  AS product,
       si.qty,
       si.unit_price,
       si.qty * si.unit_price AS line_total
FROM sales s
JOIN employees  e  ON e.id = s.employee_id
JOIN customers  c  ON c.id = s.customer_id
JOIN sale_items si ON si.sale_id = s.id
JOIN products   p  ON p.id = si.product_id
WHERE s.invoice_no IN ('INV-1001', 'INV-1005');

MySQL
SELECT c.name, c.phone
FROM customers c

WHERE s.id IS NULL;

Leaderboard: কে কত বিক্রি করল

নিজে করুন Product ধরে leaderboard বানান: কোন product মোট কয়টা বিক্রি হয়েছে আর কত টাকার (sale_items + products)।
MySQL
SELECT e.name      AS employee,
       b.name      AS branch,
       COUNT(s.id) AS invoices,
       IFNULL(SUM(s.total), 0) AS revenue
FROM employees e
JOIN branches b ON b.id = e.branch_id
LEFT JOIN sales s ON s.employee_id = e.id
GROUP BY e.id, e.name, b.name
ORDER BY revenue DESC;

লাভ: বিক্রির দাম − কেনার দাম

💡 আসল app-এ বিক্রির সময়কার কেনা দাম sale_items-এ কপি করে রাখুন — পরে product-এর cost বদলালে পুরনো লাভ যেন না বদলায়।
MySQL
SELECT p.name,
       SUM(si.qty)                              AS sold,
       SUM(si.qty * si.unit_price)              AS revenue,
       SUM(si.qty * (si.unit_price - p.cost))   AS profit
FROM sale_items si
JOIN products p ON p.id = si.product_id
GROUP BY p.id, p.name
ORDER BY profit DESC
LIMIT 5;

JOIN-এর ধরন এক নজরে

JOINকী ফেরত দেয়কখন
INNER JOIN (JOIN)দুই দিকে মিল আছে এমন rowবেশিরভাগ রিপোর্ট
LEFT JOINবাম দিকের সব + ডানের মিল"যাদের নেই" তাদেরও দেখাতে
RIGHT JOINডান দিকের সব + বামের মিলকম ব্যবহার; LEFT উল্টে লিখুন
CROSS JOINসব জোড়া (গুণফল)তারিখ × শাখা grid বানাতে
PHP/Laravel-এ যেমন Laravel: join(), leftJoin(), rightJoin(), crossJoin()।

VIEW: query-কে নাম দিয়ে রাখা

বারবার লাগে এমন জটিল query VIEW বানিয়ে রাখলে table-এর মতো ব্যবহার করা যায়।

PHP/Laravel-এ যেমন View-এর জন্যও Eloquent model বানানো যায় (protected $table = 'branch_daily_sales';) — শুধু পড়ার জন্য।
MySQL
CREATE VIEW branch_daily_sales AS
SELECT b.name AS branch, DATE(s.sold_at) AS day, SUM(s.total) AS revenue
FROM sales s
JOIN branches b ON b.id = s.branch_id
GROUP BY b.name, DATE(s.sold_at);

SELECT * FROM branch_daily_sales WHERE branch = 'Mirpur' ORDER BY day;

Eloquent relationship আসলে কোন SQL

প্রতিটি relationship property ধরলেই একটা আলাদা query চলে। একটা sale-এর জন্য সমস্যা নেই — কিন্তু ১০০টা sale-এর loop-এ?

Laravel model
class Sale extends Model {
    public function customer() { return $this->belongsTo(Customer::class); }
    public function items()    { return $this->hasMany(SaleItem::class); }
}

$sale = Sale::find(1);
$sale->customer;   // select * from customers where id = ? limit 1
$sale->items;      // select * from sale_items where sale_id = ?

N+1 সমস্যা আর with()

Loop-এ $sale->customer দিলে প্রতিটি sale-এর জন্য একটা করে query (customer থাকলে): N টা sale = ১ + N query। with('customer') দিলে মাত্র ২টা। আসল query log দেখুন MySQL for Laravel কোর্সে।

💡 Model::preventLazyLoading() development-এ চালু রাখুন — N+1 হলে Laravel নিজেই exception দেবে। বিস্তারিত MySQL for Laravel-এ।
Laravel-এ
// N+1: 1 + N queries
foreach (Sale::all() as $sale) { echo $sale->customer?->name; }

// Eager loading: 2 queries (যত sale-ই হোক)
foreach (Sale::with('customer')->get() as $sale) { echo $sale->customer?->name; }
MySQL
-- with('customer') এর দ্বিতীয় query দেখতে এরকম:
SELECT * FROM customers WHERE id IN (1, 2, 3, 4, 5);

Project: সপ্তাহের রিপোর্ট

মালিকের জন্য এক query-তে: শাখা, কর্মচারী, invoice সংখ্যা, বিক্রি আর লাভ — বেশি লাভ আগে।

নিজে করুন একই রিপোর্টে customer-এর district ধরে ভাগ করুন — walk-in বিক্রি যেন বাদ না পড়ে (কোন JOIN লাগবে?)।
MySQL
SELECT b.name AS branch,
       e.name AS employee,
       COUNT(DISTINCT s.id)                      AS invoices,
       SUM(si.qty * si.unit_price)               AS revenue,
       SUM(si.qty * (si.unit_price - p.cost))    AS profit
FROM sales s
JOIN branches   b  ON b.id = s.branch_id
JOIN employees  e  ON e.id = s.employee_id
JOIN sale_items si ON si.sale_id = s.id
JOIN products   p  ON p.id = si.product_id
WHERE s.sold_at >= '2026-10-15' AND s.sold_at < '2026-10-20'
GROUP BY b.name, e.name
ORDER BY profit DESC;
