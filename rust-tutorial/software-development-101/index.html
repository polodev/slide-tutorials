Software engineering মানে কী?

Laravel-এ php artisan make:controller চালিয়ে page বানানো application development। Software engineering তার চেয়ে বড়: কোড লেখা, বোঝা, বদলানো, নিরাপদ রাখা, দ্রুত চালানো আর দলের সাথে কাজ করা।

  • কোড একবার লেখা হয়, কিন্তু বছরের পর বছর পড়া ও বদলানো হয়
  • ভালো software = ঠিকঠাক চলে + বোঝা যায় + বদলানো সহজ + নিরাপদ + দ্রুত
  • Rust এই শেষের দুটো (নিরাপদ, দ্রুত) নিয়ে জন্মেছে — কিন্তু তার দাম হিসেবে নিচের স্তরের ধারণা জানতে চায়
PHP/Laravel-এ যেমন Laravel অনেক কিছু আপনার হয়ে করে দেয় (memory, security, routing)। Rust অনেকটা নিজের হাতে করতে দেয় — তাই আপনাকে জানতে হবে "নিচে কী হচ্ছে"। এই কোর্স সেটাই।

Computer আসলে কী বোঝে?

Computer শুধু বোঝে 0 আর 1 — বিদ্যুৎ আছে বা নেই। আপনার লেখা echo "Hello" শেষ পর্যন্ত বহু 0-1 হয়ে CPU-তে যায়। নিচে আসল সংখ্যায় দেখুন:

📘 জার্গন — শব্দের মানে
  • Bit — একটা 0 অথবা 1 — তথ্যের সবচেয়ে ছোট একক
  • Byte — ৮ bit; ইংরেজি একটা অক্ষর = ১ byte, বাংলা একটা অক্ষর = সাধারণত ৩ byte (UTF-8)
  • Binary — শুধু 0 আর 1 দিয়ে লেখা সংখ্যা
  • Machine code — CPU সরাসরি যে 0-1 নির্দেশ বোঝে
Rust
fn main() {
    println!("18 binary-তে:  {:08b}", 18);
    println!("'A' এর কোড:      {}", 'A' as u8);
    println!("'ক' কত byte:    {}", "ক".len());
    println!("1 KB = {} byte", 1024);
}
আউটপুট
18 binary-তে:  00010010
'A' এর কোড:      65
'ক' কত byte:    3
1 KB = 1024 byte

Compiler আর interpreter

মানুষের লেখা কোড (source code) CPU সরাসরি বোঝে না — অনুবাদ লাগে। অনুবাদের দুটো পথ:

Compiler (Rust, C, C++, Go)Interpreter (PHP, Python, JS-এর অনেকটা)
কখন অনুবাদচালানোর আগে, পুরোটা একবারেচলার সময়, লাইন/অংশ ধরে
ফলএকটা চালানো-যায় এমন ফাইল (binary)কোনো আলাদা ফাইল নেই; interpreter রোজ পড়ে
ভুল ধরা পড়েcompile-এ, user দেখার আগেইঅনেক ভুল চলার সময়, user-এর সামনে
গতিসাধারণত অনেক দ্রুতধীর (JIT থাকলে কিছুটা দ্রুত)
📘 জার্গন — শব্দের মানে
  • Source code — মানুষের লেখা কোড (.php, .rs ফাইল)
  • Compile — source code-কে machine code-এ বদলানো
  • Binary / executable — compile-এর ফল, সরাসরি চালানো যায়
  • Interpreter — source code পড়ে সাথে সাথে চালায়
  • Ahead-of-time (AOT) — আগেই compile — Rust এমন
PHP/Laravel-এ যেমন PHP আসলে অর্ধেক-compiler: Zend Engine আপনার কোডকে bytecode-এ বদলে নেয়, তারপর একটা virtual machine সেটা চালায়। তবে প্রতিটা request-এ এই কাজ নতুন করে (OPcache থাকলে cache থেকে)।

C: সবকিছুর দাদু

C বানিয়েছিলেন Dennis Ritchie, Bell Labs-এ, ১৯৭০-এর দশকের শুরুতে — Unix operating system লেখার জন্য। আজও Linux kernel, database engine, আর অসংখ্য device-এর ভিতরে C চলছে। PHP-র interpreter-ও C-তে লেখা!

PHP/Laravel-এ যেমন আপনি যে php command চালান, সেটা C দিয়ে লেখা program। অর্থাৎ PHP-র নিচেই C।
📘 জার্গন — শব্দের মানে
  • Kernel — operating system-এর কেন্দ্র — hardware-কে সরাসরি সামলায়
  • Standard library — ভাষার সাথে আসা তৈরি function (printf)
  • Header (#include) — অন্য file-এর function ব্যবহারের ঘোষণা আনা

পাঠ ৯

C-তে memory নিজের হাতে

C-তে চাইলে RAM থেকে জায়গা চেয়ে নিতে হয় (malloc) আর কাজ শেষে নিজে ফেরত দিতে হয় (free)। ভুলে গেলে আর কেউ মনে করিয়ে দেবে না।

⚠️ free ভুলে গেলে memory leak; দুইবার করলে crash; free-এর পর ব্যবহার করলে অজানা আচরণ। C compiler এসব আটকায় না — এই কারণেই বহু বড় security bug C/C++-এ।
📘 জার্গন — শব্দের মানে
  • malloc / free — memory চাওয়া / ফেরত দেওয়া
  • Pointer (*) — একটা জায়গার ঠিকানা — মানটা নয়, কোথায় আছে সেটা
  • Memory leak — জায়গা নিয়ে ফেরত না দেওয়া; program ধীরে ধীরে RAM খেয়ে ফেলে
  • Undefined behavior (UB) — নিয়ম ভাঙলে ভাষা কিছুই গ্যারান্টি দেয় না — crash, ভুল মান, বা চুপচাপ ভুল
C
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *prices = malloc(3 * sizeof(int));   // ৩টা সংখ্যার জায়গা চাইলাম
    if (prices == NULL) return 1;

    prices[0] = 18500;
    prices[1] = 41500;
    prices[2] = 112000;

    int sum = 0;
    for (int i = 0; i < 3; i++) sum += prices[i];
    printf("মোট: %d\n", sum);

    free(prices);                            // জায়গা ফেরত — ভুলে গেলে "leak"
    return 0;
}

C++: C + অনেক কিছু

C++ বানান Bjarne Stroustrup, ১৯৮০-র দশকে — C-র গতি রেখে তার উপর class, object, template যোগ করে। Chrome, game engine, Photoshop, অনেক trading system C++-এ। শক্তিশালী, কিন্তু অনেক জটিল — আর C-র memory-র ঝুঁকি অনেকটা রয়ে গেছে।

📘 জার্গন — শব্দের মানে
  • Class / Object — ছাঁচ / ছাঁচ থেকে বানানো জিনিস (PHP-র মতোই)
  • Template — যেকোনো type-এর জন্য একবার লেখা code — Rust-এর generic-এর পূর্বসূরি
  • std::vector — vector নামটা এখান থেকেই জনপ্রিয় — পরে আলাদা lesson
C++
#include <iostream>
#include <vector>

int main() {
    std::vector<int> prices = {18500, 41500};   // vector: বাড়তে-পারা list
    prices.push_back(112000);                   // শেষে যোগ

    int sum = 0;
    for (int p : prices) sum += p;
    std::cout << "দাম " << prices.size() << " টি, মোট " << sum << " টাকা\n";
    return 0;
}

Rust: গতি, কিন্তু নিরাপদ

Rust শুরু হয় ২০০৬ সালে Graydon Hoare-র ব্যক্তিগত প্রজেক্ট হিসেবে; পরে Mozilla (Firefox-এর নির্মাতা) সমর্থন করে। প্রথম স্থিতিশীল সংস্করণ Rust 1.0 — ২০১৫ সালে। লক্ষ্য একটাই: C/C++-এর গতি, কিন্তু memory-র ভুল compile-এই ধরা।

  • C/C++-এর মতোই compile হয়ে machine code, কোনো garbage collector নেই
  • কিন্তু ownership নিয়মে memory-র বেশিরভাগ বিপজ্জনক ভুল compile-এ আটকে যায়
  • একই ভাষায় low-level কাজও, আবার web-ও (axum, Leptos, Topcoat)
📘 জার্গন — শব্দের মানে
  • Foundation — ২০২১ সালে Rust Foundation বানানো হয় — ভাষাটা এখন কোনো এক কোম্পানির নয়
  • Stable release — পুরনো কোড ভাঙবে না এমন প্রতিশ্রুতির সংস্করণ

ভাষাগুলো সমস্যা ভাবার আলাদা আলাদা ধরন (paradigm) দেয়। বেশিরভাগ ভাষা কয়েকটা মিশিয়ে।

📘 জার্গন — শব্দের মানে
  • Inheritance — এক class আরেক class-এর সবকিছু পায় (extends) — Rust-এ নেই, তার বদলে trait আর composition
  • Composition — বড় জিনিস ছোট জিনিস জুড়ে বানানো — "class extends" না, "struct-এর ভিতরে struct"

Memory (RAM) আর variable

Variable আসলে RAM-এর একটা নাম-দেওয়া বাক্স। $price = 18500; মানে "একটা বাক্স নাও, নাম price, ভিতরে 18500"। প্রতিটা বাক্সের একটা ঠিকানা (address) আছে, আর বাক্সের আকার আছে।

PHP/Laravel-এ যেমন PHP-তে $x = 5 আর $x = 'five' একই variable-এ চলে, কারণ PHP পেছনে বাক্সের আকার নিজে ঠিক করে। Rust-এ আপনি (বা compiler) আগে থেকে জানে আকার — সেটাই গতির রহস্য।
📘 জার্গন — শব্দের মানে
  • Address — RAM-এ একটা বাক্সের ঠিকানা (একটা সংখ্যা)
  • Type — বাক্সের আকার আর ভিতরের জিনিসের ধরন
  • Allocation — বাক্সের জন্য জায়গা নেওয়া
Rust
use std::mem::size_of;

fn main() {
    println!("i32 (ছোট পূর্ণ সংখ্যা):  {} byte", size_of::<i32>());
    println!("i64 (বড় পূর্ণ সংখ্যা):   {} byte", size_of::<i64>());
    println!("f64 (দশমিক সংখ্যা):     {} byte", size_of::<f64>());
    println!("bool:                    {} byte", size_of::<bool>());
    println!("[i32; 3] (তিনটা সংখ্যা): {} byte", size_of::<[i32; 3]>());
}

Memory management: তিন পদ্ধতি

Heap-এর জায়গা কে ফেরত নেবে — এই প্রশ্নের উত্তরেই ভাষাগুলো আলাদা:

পদ্ধতিকে পরিষ্কার করেভাষাসুবিধাঅসুবিধা
Manualপ্রোগ্রামার (free)C, C++ (আংশিক)পূর্ণ নিয়ন্ত্রণ, দ্রুতভুল হয়: leak, crash, security hole
Garbage Collector (GC)ভাষার runtime, চলার সময়PHP, Java, Go, JS, Pythonসহজ, ভুল কমএকটু বেশি memory, মাঝেমধ্যে ছোট বিরতি
Ownershipcompiler, compile-এ নিয়ম দিয়েRustদ্রুত + নিরাপদ, কোনো বিরতি নেইনিয়ম শিখতে সময়
📘 জার্গন — শব্দের মানে
  • Garbage collector — পেছনে চলা প্রক্রিয়া যে আর-লাগে-না memory খুঁজে খালি করে
  • Ownership — প্রতিটা মানের একজন মালিক; মালিক চলে গেলে মান মুছে যায় — compile-এ যাচাই
  • Pause — GC চলার সময় program-এর ক্ষণিক থেমে যাওয়া — real-time কাজে সমস্যা
PHP/Laravel-এ যেমন PHP প্রতি request-এ শুরু হয়ে শেষ হলে সব memory ফেলে দেয় — তাই leak ধরা পড়ে না। Rust server একবার চালু হয়ে দিনের পর দিন চলে, তাই memory-র হিসাব জরুরি।

Rust-এর পরিষ্কার: GC ছাড়াই নিজে নিজে

Rust-এ কেউ free লেখে না, GC-ও নেই। Compiler জানে কোন variable কোথায় শেষ হবে — ঠিক সেখানেই পরিষ্কার-করার code বসিয়ে দেয়। Drop দিয়ে সেটা দেখা যায়:

💡 পরিষ্কারের সময় আগে থেকে ঠিক জানা — GC-র মতো "কখনো একসময়" না। এই নিশ্চয়তাই Rust-কে real-time আর server-এর জন্য আদর্শ করে।
Rust
struct Invoice {
    no: u32,
}

impl Drop for Invoice {
    fn drop(&mut self) {
        println!("Invoice {} পরিষ্কার হলো", self.no);
    }
}

fn main() {
    let _a = Invoice { no: 1001 };
    {
        let _b = Invoice { no: 1002 };
        println!("ভিতরের block চলছে");
    }   // ← এখানে _b-র মালিক শেষ, তাই এখনই পরিষ্কার
    println!("বাইরের block চলছে");
}   // ← এখানে _a শেষ

Garbage collection কীভাবে কাজ করে

GC-র দুটো প্রধান কৌশল। Reference counting: প্রতিটা জিনিসের গায়ে লেখা থাকে "কয়জন আমাকে ধরে আছে"; সংখ্যা ০ হলেই মুছে। Tracing: মাঝে মাঝে "মূল" জিনিস থেকে ধরে ধরে যা পৌঁছানো যায় সেগুলো রেখে বাকি সব ফেলে দেয়। PHP প্রথমটা ব্যবহার করে, সাথে একটা ছোট cycle-খোঁজা অংশ।

উপরে দুই object একে অপরকে ধরে থাকায় count কখনো ০ হতো না — শুধু refcount থাকলে leak হতো। PHP-র আলাদা cycle collector সেটা ধরেছে।

📘 জার্গন — শব্দের মানে
  • Reference counting — কয়জন ধরে আছে তার সংখ্যা রেখে, ০ হলে মোছা
  • Cycle — A → B → A — একে অপরকে ধরে থাকার চক্র; refcount একা পারে না
  • Tracing GC — মূল থেকে পৌঁছানো যায় এমন সব খুঁজে বাকিটা মোছে (Java, Go, JS)
  • Stop-the-world pause — GC চলার সময় program-এর ক্ষণিক থামা
💡 GC-র দাম: (১) অতিরিক্ত memory, (২) চলার সময় অতিরিক্ত কাজ, (৩) অনির্দিষ্ট সময়ে ছোট বিরতি। Rust এই তিনটাই বাদ দেয় — কিন্তু বিনিময়ে নিয়ম শেখায়।
PHP
<?php
class Node { public $other; }
$a = new Node(); $b = new Node();
$a->other = $b; $b->other = $a;     // দুজন একে অপরকে ধরে আছে
unset($a, $b);                       // নাম মুছলাম, কিন্তু object দুটো একে অপরকে ধরে বেঁচে আছে
echo "GC-র cycle collector মুছল: ", gc_collect_cycles(), " টি\n";

Memory safe মানে কী?

একটা ভাষা memory safe যদি তার সাধারণ (safe) কোড দিয়ে memory-র বিপজ্জনক ভুল — ভুল জায়গা পড়া, মুছে-ফেলা জিনিস ব্যবহার, দুইবার মোছা — করাই সম্ভব না হয়।

ভাষাMemory safe?কীভাবে
C, C++নাprogrammer-এর দায়িত্ব; compiler চুপ
PHP, Java, Go, Python, JSহ্যাঁGC আর runtime-এর পাহারা (চলার সময়)
Rustহ্যাঁownership + borrow checker (compile-এ), GC ছাড়া
  • বড় tech কোম্পানিদের হিসাবে প্রায় ৭০% security bug-ই ছিল memory-সংক্রান্ত — তাই সরকারি নিরাপত্তা সংস্থাগুলোও memory-safe ভাষায় যেতে বলছে
  • Rust-এর বিশেষত্ব: GC-র মতো নিরাপদ, আবার C-র মতো দ্রুত
📘 জার্গন — শব্দের মানে
  • Safe Rust — সাধারণ Rust code — memory-র ভুল করাই যায় না
  • unsafe — compiler-কে বলা "এই অংশটুকু আমি নিজে দেখছি" — খুব সীমিত জায়গায়, শেষ উপায়
  • Security vulnerability — hacker কাজে লাগাতে পারে এমন ফাঁক
⚠️ "Memory safe" মানে "সব bug-মুক্ত" না! logic-এর ভুল (ভুল দাম হিসাব), SQL injection, দুর্বল password — এগুলো যেকোনো ভাষায় সম্ভব।

Borrow checker: compiler-এর পাহারাদার

Rust-এর compiler-এর যে অংশ ownership আর ধার (borrow) নিয়ম যাচাই করে, তার নাম borrow checker। নিয়ম মাত্র দুটো: (১) একবারে একজনই বদলাতে পারে (&mut), অথবা (২) যত খুশি লোক শুধু পড়তে পারে (&) — দুটো একসাথে নয়।

কেন নিষিদ্ধ? push-এ vector বড় হয়ে নতুন জায়গায় সরে যেতে পারে — তখন first ঝুলে থাকা ঠিকানা হতো। C++-এ এটা চুপচাপ crash/ভুল ফল দেয়; Rust compile-এ থামায়।

📘 জার্গন — শব্দের মানে
  • Borrow — মালিকানা না দিয়ে অস্থায়ীভাবে ব্যবহার করতে দেওয়া
  • Borrow checker — ধার-নিয়ম compile-এ যাচাই করে
  • Data race — একাধিক জন একসাথে একই data বদলানো/পড়া — borrow নিয়মই এটা অসম্ভব করে
PHP/Laravel-এ যেমন PHP-তে $first = $cart[0]; $cart[] = 112000; নির্বিঘ্নে চলে, কারণ $first একটা কপি। Rust-এ & মানে কপি না, সরাসরি ঠিকানা — তাই নিয়ম কড়া।
Rust
fn main() {
    let mut cart = vec![18500, 41500];

    let first = &cart[0];          // পড়ার জন্য ধার নিলাম
    cart.push(112000);             // কিন্তু এদিকে বদলাতে চাইছি!
    println!("প্রথম দাম: {first}");
}

Borrow checker: আরও দুই দৃশ্য

একসাথে দুজন লেখক (&mut) নিষিদ্ধ, আর মালিকানা চলে গেলে পুরনো নাম অচল।

💡 Borrow checker প্রথমে বিরক্তিকর লাগে — সবাই এটাকে "fighting the borrow checker" বলে। কিন্তু প্রতিটা error আসলে একটা সম্ভাব্য production bug, যা আপনার user কখনো দেখবে না।

fn main() {

    let a = &mut stock;
    let b = &mut stock;      // দ্বিতীয় লেখক!
    *a -= 1;
    *b -= 1;
    println!("{stock}");
}

Algorithm আর Big-O

Algorithm = একটা কাজ করার ধাপের তালিকা। একই কাজের একাধিক পথ থাকে; কোনটা কত ধাপ নেয় — সেটা মাপার ভাষা Big-O। ধরুন ফোনের তালিকায় একটা নাম খুঁজছেন: প্রথম থেকে একটা একটা করে (linear), না মাঝখান থেকে আধা আধা করে (binary, শর্ত: তালিকা সাজানো)?

📘 জার্গন — শব্দের মানে
  • Big-O notation — ডেটা বাড়লে ধাপ কত বাড়ে তার হিসাব
  • O(1) — ডেটা যত-ই হোক ধাপ এক (index ধরে পড়া)
  • O(n) — ডেটার সাথে সমান হারে বাড়ে (linear search)
  • O(log n) — ডেটা কয়েক গুণ হলেও ধাপ সামান্য বাড়ে (binary search — উপরে ১০ লক্ষে মাত্র ২০ ধাপ)
  • O(n²) — ডেটা ১০ গুণ → ধাপ ১০০ গুণ; বড় ডেটায় বিপজ্জনক (loop-এর ভিতরে loop)
PHP/Laravel-এ যেমন Laravel-এর N+1 query সমস্যা আসলে এই কথাই: ১০০ order দেখাতে ১০১টা query। ডেটা বাড়লে ধাপ খুব দ্রুত বাড়ে — Big-O-র দৃষ্টিতে সেটাই দুর্বলতা।
Rust
fn linear(list: &[u32], target: u32) -> u32 {
    let mut steps = 0;
    for &x in list {
        steps += 1;
        if x == target { break; }
    }
    steps
}

fn binary(list: &[u32], target: u32) -> u32 {
    let (mut lo, mut hi) = (0usize, list.len());
    let mut steps = 0;
    while lo < hi {
        steps += 1;
        let mid = (lo + hi) / 2;
        if list[mid] == target { break; }
        else if list[mid] < target { lo = mid + 1; }
        else { hi = mid; }
    }
    steps
}

fn main() {
    for n in [10u32, 1_000, 1_000_000] {
        let list: Vec<u32> = (1..=n).collect();
        println!("{n:>9} টা product: linear {:>7} ধাপ, binary {:>2} ধাপ", linear(&list, n), binary(&list, n));
    }
}

📘 জার্গন — শব্দের মানে

fn factorial(n: u64) -> u64 {
    if n <= 1 { 1 } else { n * factorial(n - 1) }
}

fn main() {
    println!("5! = {}", factorial(5));
    println!("10! = {}", factorial(10));
}

Pointer আর reference

Pointer/reference = মান নয়, মানটা যেখানে আছে তার ঠিকানা। বড় জিনিস কপি না করে ঠিকানা দিলে দ্রুত — কিন্তু ঠিকানা ভুল হলে (জিনিস মুছে গেছে) বিপদ। Rust-এ & চিহ্ন reference, আর borrow checker নিশ্চিত করে ঠিকানাটা সবসময় বৈধ।

📘 জার্গন — শব্দের মানে
  • Pointer — ঠিকানা (C-তে ভুল পথে যেতে পারে)
  • Reference (&) — Rust-এর নিরাপদ pointer — borrow checker যাচাই করে
  • Smart pointer — ঠিকানার সাথে বাড়তি দায়িত্ব (মুছে ফেলা, গোনা) — C++ unique_ptr, Rust Box/Rc
  • Segmentation fault (seg fault) — program এমন memory ছুঁয়েছে যা তার নয় — OS জোর করে বন্ধ করে
Rust
fn total(prices: &Vec<i32>) -> i32 {      // &: শুধু ঠিকানা, কপি না
    prices.iter().sum()
}

fn main() {
    let cart = vec![18500, 41500, 112000];
    let t1 = total(&cart);                 // ধার দিলাম
    let t2 = total(&cart);                 // আবার ধার দিলাম — cart এখনো আমার
    println!("{t1} {t2} {}", cart.len());
}

ভাষার ব্যাকরণ: syntax-এর শব্দ

ভাষা শেখার সময় এই শব্দগুলো বারবার আসে। একটা ছোট লাইনে সবগুলো দেখুন:

📘 জার্গন — শব্দের মানে
  • Keyword — ভাষার সংরক্ষিত শব্দ (let, fn, if) — নাম হিসেবে ব্যবহার নিষেধ
  • Identifier — আপনার দেওয়া নাম (variable, function)
  • Literal — সরাসরি লেখা মান (18500, "text")
  • Operator — + - * / == ইত্যাদি চিহ্ন
  • Syntax — ব্যাকরণ — কীভাবে লিখতে হবে

Generic: একবার লিখে সব type-এ

ভিডিওতে "largest item in a list" function-টা এখানে। Generic (<T>) মানে "যেকোনো type, তবে শর্ত মানতে হবে"। শর্তটাকে বলে trait bound (এখানে PartialOrd = তুলনা করা যায়)।

📘 জার্গন — শব্দের মানে
  • Generic (<T>) — type-কে চলক করা — একই code বহু type-এ
  • Trait / trait bound — type-এর চুক্তি / "এই চুক্তি মানলে তবেই" শর্ত
  • Zero-cost abstraction — সুবিধাজনক ভাষা-গঠন যার জন্য চলার সময় বাড়তি খরচ নেই — compile-এ সব খুলে যায়
Rust
fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut big = &list[0];
    for item in list {
        if item > big { big = item; }
    }
    big
}

fn main() {
    println!("{}", largest(&[18500, 41500, 112000]));
    println!("{}", largest(&[1.5, 9.25, 3.0]));
    println!("{}", largest(&["Mirpur", "Uttara", "Gulshan"]));
}

অর্থউদাহরণ
১. সময়: program চলার সময় (compile time-এর উল্টো)"এই ভুল runtime-এ ধরা পড়ে"

Concurrency-র bug compile-এ

দুই thread একসাথে একই সংখ্যা বদলালে (data race) ফল এলোমেলো। অন্য ভাষায় এটা চলার সময় কখনো-কখনো ধরা পড়ে, কখনো ধরাই পড়ে না। Rust compile-এই থামায়:

ঠিক পথ: Arc (অনেক thread মালিক) + Mutex (একবারে একজন):

📘 জার্গন — শব্দের মানে
  • Thread — program-এর ভিতরে একটা আলাদা কাজের সুতো
  • Data race — একাধিক thread একসাথে একই data পড়া/বদলানো, অন্তত একজন বদলাচ্ছে — ফল অনির্দিষ্ট
  • Mutex — তালা: একবারে একজনই ভিতরে
  • Arc — Atomically Reference Counted — thread-নিরাপদ ভাগাভাগির মালিকানা

use std::thread;

fn main() {

        sold += 1;                    // অন্য thread-এ আমার variable বদলাচ্ছি!
    });
    handle.join().unwrap();
    println!("{sold}");
}

use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let sold = Arc::new(Mutex::new(0));
    let mut handles = vec![];
    for _ in 0..4 {
        let sold = Arc::clone(&sold);
        handles.push(thread::spawn(move || {
            for _ in 0..1000 {
                *sold.lock().unwrap() += 1;
            }
        }));
    }
    for h in handles { h.join().unwrap(); }
    println!("মোট বিক্রি: {}", *sold.lock().unwrap());
}

ভিডিও ১: Systems programming language

ভিডিও বলছে "Rust is a systems programming language"। মানে কী?

📘 জার্গন — শব্দের মানে
  • Systems programming — যে software অন্য software-এর নিচে বসে: operating system, database, browser engine, network server, driver — যেখানে গতি আর memory-র উপর নিয়ন্ত্রণ জরুরি
  • Application programming — user-এর কাজের software: invoice page, shop website — Laravel-এর জগৎ
  • Low-level control — memory/CPU-র সাথে সরাসরি, বেশি কাছ থেকে কাজ করার ক্ষমতা

ভিডিও আরও বলছে Rust "as fast as C, as safe as Java, and as expressive as Python"। শব্দ-বিশ্লেষণ:

অংশমানে
as fast as Cগতি C-র সমান (compile + GC নেই)
as safe as Javamemory-র ভুল Java-র মতোই নিরাপদ (কিন্তু GC ছাড়া)
as expressive as Pythonexpressive = অল্প কোডে অনেক কিছু প্রকাশ করা যায়; iter().map().sum(), match, enum ইত্যাদি
PHP/Laravel-এ যেমন "Memory safety without garbage collection" = PHP/Java-র মতো নিরাপদ, কিন্তু GC-র পেছনে-চলা কাজ ছাড়া।

ভিডিও ১: ভিডিওর দুই code

ভিডিওতে বলা হয়েছিল: C-তে malloc করে free করে আবার ব্যবহার করলে compile হয়ে যায় — এটা use-after-free। (নিচের C code শুধু দেখানোর জন্য — চালালে ফল অনির্দিষ্ট, তাই চালাইনি।)

Rust-এ ভিডিওর সমান উদাহরণ — "create a box, drop it, try to use it":

📘 জার্গন — শব্দের মানে
  • Box — heap-এ একটা মান রাখার smart pointer
  • drop — মান মুছে memory ফেরত দেওয়া (Rust-এ সাধারণত নিজে নিজেই হয়)
  • Security vulnerability — hacker কাজে লাগাতে পারে এমন ফাঁক — ভিডিওর "70%" দাবিটা Microsoft-এর বলা: তাদের security bug-এর প্রায় ৭০% memory-সংক্রান্ত
C — compile হয়, বিপজ্জনক
#include <stdlib.h>

int main(void) {
    char *p = malloc(10);   // memory চাইলাম
    free(p);                // ফেরত দিলাম
    p[0] = 'x';             // ফেরত-দেওয়া জায়গায় লিখছি — compile হয়, কিন্তু security ফাঁক
    return 0;
}

ভিডিও ১: Performance-এর শব্দ

Discord-এর গল্প: তাদের এক service Go-তে ছিল, আর Go-র GC প্রায় প্রতি ২ মিনিটে একবার বড় পরিষ্কারে নামত — ফলে সব user-এর app ক্ষণিক আটকে যেত। Rust-এ নিয়ে ফেলায় (ভিডিওর ভাষায়) "১০ গুণ" দ্রুত হলো আর সেই বিরতি গেল।

📘 জার্গন — শব্দের মানে
  • GC pause / spike — GC চলার সময় program-এর ক্ষণিক থেমে যাওয়া বা হঠাৎ বেড়ে-যাওয়া সময় (latency spike)
  • Overhead — আসল কাজের বাইরে বাড়তি খরচ (GC-র সময়, memory)
  • Latency — এক কাজের সময় — "স্পাইক" মানে হঠাৎ এটা অনেক বেড়ে যাওয়া
  • Throughput — নির্দিষ্ট সময়ে কত কাজ হয় (সেকেন্ডে কত request)
  • 10x (দশ গুণ) — ভিডিওর দাবি — নির্দিষ্ট service-এর নির্দিষ্ট মাপে; সব app-এ ১০ গুণ আশা করা ভুল
  • Benchmark — একই কাজে দুই জিনিসের গতি মাপার পরীক্ষা — ফল নির্ভর করে কী মাপা হলো তার উপর
⚠️ "Discord ১০ গুণ দ্রুত পেয়েছে" শোনার পর "আমার Laravel app-ও Rust-এ ১০ গুণ দ্রুত হবে" ভাবা ঠিক না। তাদের সমস্যা ছিল একটা নির্দিষ্ট GC pause; আপনার app-এর সমস্যা হয়তো ধীর query।

ভিডিও ১: Rust লেখার অভিজ্ঞতা

বক্তা বলেছেন তিনি Java developer হিসেবে সব জায়গায় for loop লিখতেন, iterator method জানতেন না। দুটো একই ফল দেয়; Rust-এ দ্বিতীয়টাই স্বাভাবিক:

📘 জার্গন — শব্দের মানে
  • Iterator method — map, filter, sum — list-কে ধাপে ধাপে বদলানোর method (Laravel Collection-এর মতো)
  • Fighting the borrow checker — borrow checker বারবার কোড নাকচ করছে, আর আপনি বুঝছেন না কেন — Rust শেখার প্রথম দিকের সাধারণ অভিজ্ঞতা
  • Learning curve — শেখার কষ্টের ঢাল: কতটা সময়ে স্বচ্ছন্দ হওয়া যায় (ভিডিও: ৩–৬ মাস)
  • Mental model — একটা বিষয় আপনার মাথায় কীভাবে কাজ করে ভাবা — GC-ভাষা থেকে এলে ownership-র নতুন "মনের ছবি" বানাতে হয়
  • Onboarding — নতুন লোক কাজে স্বচ্ছন্দ হওয়ার প্রক্রিয়া
💡 ভিডিওর সেই "vector-এর reference নিয়ে push" ঝামেলা আমরা আগেই দেখেছি (Borrow checker lesson, E0502)। আর "vec macro নাকি Vec" — দুটোই এক জিনিস বানায়।
Rust
fn main() {
    let prices = [18500, 41500, 112000, 1200];

    // for loop (Java-মনের লেখা)
    let mut total = 0;
    for p in prices {
        if p > 10000 { total += p; }
    }

    // iterator method (Rust-স্টাইল): filter + sum
    let total2: i32 = prices.iter().filter(|&&p| p > 10000).sum();

    println!("{total} {total2}");
}

ভিডিও ১: Lifetime — concept fatigue-র একটা

ভিডিও বলছে Rust-এ ownership, borrowing, lifetime, trait, generic, macro, async/await — একসাথে অনেক ধারণা ("concept fatigue")। এর অনেকগুলো আমরা দেখেছি; lifetime নতুন। নিচে compiler জিজ্ঞেস করছে "ফেরত-দেওয়া reference কার জীবন ধরে বাঁচবে?":

সমাধান: একটা lifetime নাম ('a) দিয়ে বলে দেওয়া — "ফল আর দুই input একই সময় পর্যন্ত বাঁচে":

📘 জার্গন — শব্দের মানে
  • Lifetime — একটা reference কতক্ষণ বৈধ — compiler নিশ্চিত করে reference তার আসল মানের চেয়ে বেশিদিন বাঁচে না

  • Trait / Generic / Async — চুক্তি / যেকোনো type / অপেক্ষার সময় অন্য কাজ — আগের lesson-গুলোতে

  • Port to Go vs Rust — তাদের পুরনো code-এ ছিল অনেক পরস্পর-জড়ানো object (graph), যা Rust-এর ownership নিয়মে বসানো কঠিন; Go-তে (GC আছে) প্রায় সরাসরি নেওয়া গেল — ~১ বছর, Rust-এ অনেক বছর লাগত
  • Unsafe code — compiler-এর পাহারা বন্ধ-করা অংশ — ভিডিও: Rust-এ করতে গেলে প্রচুর unsafe বা নিজের GC বানাতে হতো, যা Rust-এর উদ্দেশ্যই নষ্ট করে
  • Design goal — ভাষা বানানোর সময় যে লক্ষ্য ঠিক করা — Rust-এর লক্ষ্য "পুরনো Java code সহজে port করা" নয়
  • Time to market — ধারণা থেকে বাজারে পৌঁছাতে কত সময় — Go/PHP এখানে এগিয়ে
  • Rapid prototyping — দ্রুত একটা কাঁচা সংস্করণ বানিয়ে ধারণা পরীক্ষা — Laravel এখানে দারুণ
  • Integration — নতুন system পুরনোর সাথে জোড়া লাগানো — Java/.NET/C++ বিনিয়োগ থাকলে খরচ বেশি
  • Trade-off — একটা পেতে আরেকটা ছাড়া — গতি বনাম শেখার সহজতা
💡 পাঠ: "সেরা ভাষা" বলে কিছু নেই — আছে "এই সমস্যার জন্য উপযুক্ত ভাষা"।

ভিডিও ২: Boilerplate আর WebAssembly-র ঝামেলা

ভিডিওর মূল বক্তব্য: Topcoat-এর ফিচারগুলো "requires little or no boilerplate"। আর অন্য Rust framework-এর interactivity WebAssembly-তে — যা শক্তিশালী কিন্তু "caveat" আছে:

📘 জার্গন — শব্দের মানে
  • Boilerplate — বারবার লিখতে হয় এমন একঘেয়ে কাঠামো-কোড — যত কম, তত ভালো
  • WebAssembly (WASM) — browser-এ চলার জন্য compile করা binary; Rust compile করে এখানে নেওয়া যায় (Leptos এভাবে)
  • Caveat — সতর্কতা/সীমাবদ্ধতা; "it comes with caveats" = এর সাথে কিছু অসুবিধাও আছে
  • Browser API — browser-এর দেওয়া সুবিধা: localStorage, fetch, camera, clipboard — JavaScript সরাসরি পায়; WASM-কে মাঝখানে "সেতু" লাগে (ঝামেলা)
  • JavaScript library — অন্য মানুষের লেখা JS code (chart, date-picker) — WASM থেকে ডাকা কষ্টকর
  • Escape hatch — নিয়মের বাইরে যাওয়ার দরজা: যা framework সরাসরি পারে না, তা নিজে করার সুযোগ — Topcoat-এ raw! macro দিয়ে সরাসরি JavaScript লেখা যায়
  • Friction — কাজ ধীর বা কষ্টকর করা ছোট ছোট বাধা
💡 Leptos (আমাদের আগের course) WASM ব্যবহার করে; Topcoat করে না — দুটোর পার্থক্যের মূল এটাই।

ভিডিও ২: Procedure — server function-কে client থেকে ডাকা

ভিডিওর "procedure": একটা সাধারণ async fn লিখে #[procedure] attribute দিলে সেটা server-এ চলে, কিন্তু browser-এর expression থেকে সাধারণ async function-এর মতো .await করে ডাকা যায়। Topcoat HTTP endpoint আর client-এর request code দুটোই নিজে বানায়।

📘 জার্গন — শব্দের মানে
  • Async function — যে function অপেক্ষার সময় অন্য কাজ করতে দেয় (.await)
  • Attribute (#[procedure]) — function-এর উপরের নির্দেশ — compiler/macro-কে বলে "এর সাথে বাড়তি কিছু বানাও"
  • RPC — Remote Procedure Call: দূরের function-কে নিজের function-এর মতো ডাকা
  • Seamless — মসৃণ — জোড়ার দাগ বোঝা যায় না
  • HTTP endpoint — network-এ একটা URL যেখানে request নেওয়া হয়
💡 আসল চালানো উদাহরণ: Rust Topcoat কোর্সে "Procedure: browser থেকে server function" lesson।
src/notes.rs
#[procedure]
async fn save_note(cx: &Cx, text: String) -> Result<()> {
    // server-এ চলে: database-এ লেখা (সত্যিকারের demo আমাদের Topcoat course-এ)
    Ok(())
}

ভিডিও ২: Database আর Neon

ভিডিওর স্পনসর অংশে Postgres database-এর কিছু ধারণা আছে, যেগুলো যেকোনো production app-এ লাগে:

📘 জার্গন — শব্দের মানে
  • PostgreSQL (Postgres) — জনপ্রিয় open-source relational database — MySQL-এর মতো কিন্তু আরও শক্তিশালী
  • Provider / managed database — database নিজে চালানোর বদলে যে কোম্পানি আপনার জন্য চালায় (Neon তেমন একটা)
  • Database instance — চলমান একটা database-এর কপি
  • Connection URL — database-এ ঢোকার ঠিকানা + পাসওয়ার্ড একসাথে: postgres://user:pass@host/db
  • .env file — গোপন সেটিং (পাসওয়ার্ড, URL) রাখার ফাইল — Laravel-এও আছে; কখনো Git-এ তোলা হয় না
  • CLI — Command-Line Interface — terminal থেকে চালানো tool (neon, topcoat, cargo)
  • Database branching — Git branch-এর মতো database-এর কপি বানানো: আসল ডেটায় হাত না দিয়ে পরীক্ষা
  • Review app / dev environment — pull request বা পরীক্ষার জন্য আলাদা অস্থায়ী app/পরিবেশ — প্রতিটার নিজস্ব database branch
  • Production (prod) — আসল user যে সংস্করণ ব্যবহার করছে — এখানে ভুল মানে আসল ক্ষতি
  • Automatic backup — নিজে নিজে নিয়মিত কপি রাখা
  • Point-in-time recovery (PITR) — "গতকাল বিকেল ৩:১৫ যেমন ছিল" ঠিক সেই অবস্থায় database ফিরিয়ে আনা
  • Data anonymization — আসল ডেটার নাম/ফোন ইত্যাদি বদলে পরীক্ষার কাজে নিরাপদে ব্যবহার
  • Free plan / sponsor — ভিডিওর প্রযোজক Neon-কে প্রচার করছেন — প্রযুক্তিগত সুপারিশ নয়, বিজ্ঞাপন; যেকোনো Postgres দিয়েই কাজ হয়
PHP/Laravel-এ যেমন Laravel-এ .env-এ DB_URL, php artisan migrate আর staging database — একই ধারণা; branching তার ওপর বাড়তি সুবিধা।

ভিডিও ২: App context আর request context

বক্তা বলছেন "axum-এর with_state-এর মতো" আর "axum আর Topcoat একই GitHub org-এর" — দুটোই সত্য: tokio-rs অর্গানাইজেশনে দুটোই।

📘 জার্গন — শব্দের মানে
  • App context — সব request-এ ভাগ হওয়া মান যা এক request-এর চেয়ে বেশিদিন বাঁচে — যেমন database pool
  • Database pool — আগে থেকে খুলে রাখা কয়েকটা connection; request এলে একটা ধার নেয়, শেষে ফেরত দেয়
  • Request context (Cx) — এক request-এর সব তথ্য ও হাতল: HTTP header/path/method, signal বানানো, app context পড়া
  • HTTP method — GET, POST… request-এর ধরন
  • Server handler — server-এ চলে এমন অংশ: page, layout, route, component, procedure, shard
  • Keyed by type — মানটা খোঁজা হয় তার Rust type দিয়ে — তাই let db: &Database = app_context(cx) লিখলেই হলো
  • with_state (axum) — axum-এর সমান ধারণা: router-এ shared মান জুড়ে দেওয়া
  • GitHub org — একই সংগঠনের অধীনে প্রকল্পগুলো — তাই দুটোর নকশা-ভাবনা মেলে

ভিডিও ২: Shard, DOM merge আর latency

"Shard": যে component-এর argument বদলালে server আবার সেই অংশের HTML বানিয়ে পাঠায়, আর browser সেটা পুরনো অংশের জায়গায় মিলিয়ে (merge) দেয়। ভিডিওর শব্দগুলো:

📘 জার্গন — শব্দের মানে
  • Shard — আলাদা HTTP endpoint-ওয়ালা server-component; শুধু নিজের অংশ আবার আঁকে — তাই একটা optimization
  • Re-render — আবার আঁকা
  • DOM / merge into the DOM — browser-এর page-tree; নতুন HTML পুরো বদলে না ফেলে মিলিয়ে দেওয়া যাতে focus/scroll নষ্ট না হয়
  • Server-read signal — signal server-ও পড়ে (runtime expression-এর বাইরে) — বদলালে পুরো page server-এ আবার আঁকা হয়; shard হলে শুধু সেই অংশ
  • Server round trip — browser → server → browser পুরো যাওয়া-আসা; এতে সময় লাগে = latency
  • In-flight request — পাঠানো হয়েছে কিন্তু উত্তর আসেনি এমন request
  • Coalescing — একই "tick"-এ (এক ঝলকে) একাধিক পরিবর্তন জুড়ে একটাই request পাঠানো
  • Abort previous request — নতুন পরিবর্তন এলে আগের পাঠানো request বাতিল
  • Latest wins — সবসময় শেষ মানের উত্তরটাই ব্যবহার — পুরনো ধীর উত্তর নতুনের উপর বসে যায় না

ভিডিও ২: Memoization আর single-flight

ভিডিওর শেষ বড় ফিচার #[memoize]। একটা request-এর মধ্যে একই function একই argument-এ দুবার ডাকলে দ্বিতীয়বার database না গিয়ে আগের ফল দেয়। নিচে ধারণার ছোট মডেল (দুটো আসল আউটপুটের তুলনা):

📘 জার্গন — শব্দের মানে
  • Memoization — ফাংশনের ফল তার argument অনুযায়ী মনে রাখা (cache); একই argument-এ আবার হিসাব না করা
  • Per-request cache — শুধু এক request-এর জন্য বেঁচে থাকে — request শেষে মুছে যায়, তাই পুরনো-ডেটার ভয় নেই
  • Keyed by arguments — cache-এর চাবি হলো function-এর argument
  • Single-flight — একই মুহূর্তে একই কাজের অনেকগুলো অনুরোধ এলে আসলে একটাই চলে, বাকিরা তার ফলের জন্য অপেক্ষা করে — ১০ জন গ্রাহক একসাথে দাম জিজ্ঞেস করলে ক্যাশিয়ার একবারই দেখে সবাইকে বলে
  • Sync vs async function — sync: শেষ না হওয়া পর্যন্ত আটকে থাকে; async: অপেক্ষার সময় ছেড়ে দেয়
PHP/Laravel-এ যেমন Laravel-এ $user = once(fn () => User::find(7)) বা Cache::remember() — একই ধারণা। N+1 সমস্যা সারানোর একটা পথ।
Rust
use std::collections::HashMap;

fn get_user(id: u32, db_calls: &mut u32) -> String {
    *db_calls += 1;
    println!("  database query: user {id}");
    format!("user-{id}")
}

fn main() {
    println!("memoize ছাড়া:");
    let mut calls = 0;
    let a = get_user(7, &mut calls);
    let b = get_user(7, &mut calls);
    println!("  {a}, {b} — database ডাক: {calls}");

    println!("memoize সহ (ফল মনে রাখি):");
    let mut cache: HashMap<u32, String> = HashMap::new();
    let mut calls = 0;
    for _ in 0..2 {
        let user = cache.entry(7).or_insert_with(|| get_user(7, &mut calls));
        println!("  পেলাম {user}");
    }
    println!("  database ডাক: {calls}");
}

📘 জার্গন — শব্দের মানে

  • Bottleneck — পুরো system-এর ধীরতম অংশ — এটা না সারালে বাকি সব সারানো বৃথা
  • Profiling — program-এর কোন অংশ কত সময়/memory খাচ্ছে মেপে দেখা
  • Caching — ঘন ঘন লাগে এমন ফল কাছে রাখা
  • Premature optimization — মাপার আগেই কোড জটিল করে "দ্রুত" বানানো — "মাপো, তারপর বদলাও"
  • CPU-bound / I/O-bound — হিসাবে আটকা / অপেক্ষায় আটকা
⚠️ বেশিরভাগ Laravel app-এর bottleneck: database query (N+1, index নেই) আর network। আগে profile করুন — ভাষা বদলানোর আগে।

Stack ছোট, নির্দিষ্ট-আকারের মানের জন্য দ্রুত জায়গা; function শেষে নিজে নিজে সাফ। Heap বড়, বাড়তে-পারা মানের জন্য (লেখা, vector), ধীর, আর কাউকে পরিষ্কার করতে হয় (C: আপনি, PHP: GC, Rust: ownership)।

❓ Garbage collector ছাড়া Rust memory কীভাবে সাফ করে?

Ownership: প্রতিটা মানের একজন মালিক; মালিকের scope শেষ হলে compiler ঠিক সেখানেই সাফ করার কোড বসায়। কখন সাফ হবে তা আগে থেকেই নির্দিষ্ট — কোনো পেছনের প্রক্রিয়া বা বিরতি নেই।

❓ Borrow checker কী আটকায়?

যে reference ঝুলে থাকতে পারে, বা একসাথে কেউ বদলাচ্ছে আর কেউ পড়ছে এমন পরিস্থিতি। নিয়ম: একসাথে একজন লেখক (&mut) অথবা অনেক পাঠক (&)। এতে use-after-free, data race compile-এই বন্ধ।

❓ Memory safe মানে কি bug-মুক্ত?

না। শুধু memory-র নির্দিষ্ট ধরনের ভুল (overflow, use-after-free ইত্যাদি) হয় না। Logic-এর ভুল, SQL injection, দুর্বল পাসওয়ার্ড — যেকোনো ভাষায় সম্ভব।

❓ Compiler আর interpreter-এর মূল পার্থক্য?

Compiler চালানোর আগে পুরো কোড machine code-এ বদলে (ভুল compile-এই ধরা পড়ে, program দ্রুত); interpreter চলার সময় পড়ে চালায় (নমনীয়, কিন্তু ধীর এবং ভুল runtime-এ)।

❓ Vector আর array-র পার্থক্য?

Array-র সংখ্যা নির্দিষ্ট; vector বাড়তে-কমতে পারে (ভিতরে array, ভরে গেলে বড় জায়গায় সরে — length আর capacity আলাদা)। PHP-র array দুটোই (এবং hash map)।

❓ Rewrite-এর বদলে strangler পদ্ধতি কেন ভালো?

এক সাথে একটা অংশ নতুনে নিয়ে বাকিটা পুরনোতে রেখে চলা যায়, ভুল হলে শুধু সেই অংশ rollback হয়, ব্যবসা থামে না।
