Rust Topcoat
Tokio-র Full-stack Framework

Tokio আর axum যারা বানিয়েছেন, সেই টিমেরই নতুন framework: Laravel-এর মতো page, layout, route, form — সব Rust-এ, আর interactivity আসে WebAssembly ছাড়াই। প্রতিটি উদাহরণ আসলেই চালানো।

  • Topcoat কী আর Leptos/axum থেকে কীভাবে আলাদা
  • view! macro: if, for, match
  • async component আর child
  • Module routing, layout, path/query parameter
  • API route আর error
  • Request context (Cx) আর shared app state
  • Form আর redirect
  • $() runtime: signal, event, procedure, shard

আগে জানা দরকার: Rust 101–103 আর Rust Web Development (axum)। Leptos পড়া থাকলে তুলনা বুঝতে সুবিধা।

→ তীর চাপুন বা swipe করুন · M সব পাঠের তালিকা · অগ্রগতি নিজে থেকেই সেভ হয়

পাঠ ১

Topcoat কী?

Topcoat হলো Tokio টিমের (Carl Lerche ও Julien Scholz) বানানো full-stack web framework। এটা axum-এর উপর বসানো — axum যেখানে শুধু HTTP, Topcoat সেখানে page, layout, form, session আর browser interactivity-ও দেয়।

  • Server-first — HTML বানানো হয় server-এ (Rust-এ)
  • WebAssembly নেই — browser-এর অংশটুকু ছোট JavaScript-এ compile হয়
  • Component async — সরাসরি database query করা যায়
  • Module tree থেকেই URL (src/app/about.rs → /about)
⚠️ Topcoat এখনো early-stage ও experimental (0.10)। API বদলাতে পারে — শেখার জন্য দারুণ, কিন্তু গুরুত্বপূর্ণ production app এখনই এতে সরাবেন না।

পাঠ ৪

Topcoat-এর জার্গন: server-first

📘 জার্গন — শব্দের মানে
  • Server-first — প্রধান কাজ server-এ; browser-এ শুধু যতটুকু না হলেই নয়
  • Async component — component-এর ভিতরে .await করা যায় — database query সরাসরি
  • Layout — অনেক page-এর সাধারণ খোল (nav, footer) — Blade-এর @extends
  • Routing — URL দেখে কোন code চলবে তা ঠিক করা; Topcoat-এ module tree-ই
  • RPC (Remote Procedure Call) — দূরের function-কে নিজের function-এর মতো ডাকা — #[procedure] এমনই
  • Early-stage / experimental — API বদলাবে — production-এ ঝুঁকি আছে

প্রথম Hello, World!

সবচেয়ে ছোট Topcoat app। #[page] একটা URL-এর handler, view! HTML বানায়, আর #[component] function view-এর ভিতর থেকে নাম ধরে ডাকা যায়: hello(name: "World")। নিচে server-এর আসল response।

PHP/Laravel-এ যেমন Route::get('/', fn () => view('home'))-এর জায়গায় #[page] function। আর কোনো route ফাইল নেই।
Rust
use topcoat::{
    Result,
    router::{module_router, page},
    view::{View, component, view},
};

#[tokio::main]
async fn main() {
    topcoat::start(module_router!().build()).await.unwrap();
}

#[page]
async fn home() -> Result<impl View> {
    Ok(view! {
        <!DOCTYPE html>
        <html>
            <head>
                <title>"Hello world"</title>
            </head>
            <body>
                hello(name: "World")
            </body>
        </html>
    })
}

#[component]
async fn hello(name: &str) -> Result<impl View> {
    Ok(view! {
        <h1>"Hello, " (name) "!"</h1>
    })
}
Response (curl)

Rust value বসানো: ( )

Blade-এ {{ $name }}, Topcoat-এ (name) — গোল বন্ধনীর ভিতরে যেকোনো Rust expression। Text-এ আর attribute-এর মান — দুই জায়গাতেই।

PHP/Laravel-এ যেমন Blade-এর {{ }}-এর মতো এখানেও value HTML-escape হয়ে বসে — user-এর লেখা সরাসরি HTML হবে না।
Rust
use topcoat::{Result, router::{module_router, page}, view::{View, view}};

#[tokio::main]
async fn main() {
    topcoat::start(module_router!().build()).await.unwrap();
}

#[page]
async fn home() -> Result<impl View> {
    let name = "Samsung A55";
    let price = 41500;
    let url = "/products/2";
    Ok(view! {

        <p>"VAT সহ: " (price * 115 / 100)</p>
        <a href=(url)>"বিস্তারিত"</a>
    })
}

if: শর্ত

if, else if, else — সরাসরি Rust-এর মতো, ভিতরে markup। Attribute-এর জায়গাতেও চলে (শর্ত মিললে attribute যোগ হবে)।

PHP/Laravel-এ যেমন @if ($stock > 5) ... @elseif ... @else ... @endif — একই গঠন, শুধু @ আর end... ছাড়া।
Rust
use topcoat::{Result, router::{module_router, page}, view::{View, view}};

#[tokio::main]
async fn main() {
    topcoat::start(module_router!().build()).await.unwrap();
}

#[page]
async fn home() -> Result<impl View> {
    let stock = 2;
    Ok(view! {
        if stock > 5 {
            <p>"স্টকে আছে"</p>
        } else if stock > 0 {
            <p class="low">"মাত্র " (stock) " টি বাকি!"</p>
        } else {
            <p>"স্টক শেষ"</p>
        }
        <a href="/cart" if stock < 5 { aria-label="কম স্টক" class="warn" }>"Cart"</a>
    })
}
Response (curl)
$ curl -s http://localhost:3000/
<p class="low">মাত্র 2 টি বাকি!</p><a aria-label="কম স্টক" class="warn" href="/cart">Cart</a>

for: list

for item in list { ... } — @foreach-এর জায়গায় সাধারণ Rust loop।

Rust
use topcoat::{Result, router::{module_router, page}, view::{View, view}};

struct Product { name: &'static str, price: u32 }

#[tokio::main]
async fn main() {
    topcoat::start(module_router!().build()).await.unwrap();
}

#[page]
async fn home() -> Result<impl View> {
    let products = vec![
        Product { name: "iPhone 15", price: 112000 },
        Product { name: "Samsung A55", price: 41500 },
        Product { name: "Redmi 13", price: 18500 },
    ];
    Ok(view! {
        <ul>
            for p in products {
                <li>(p.name) " — " (p.price) " Taka"</li>
            }
        </ul>
    })
}
Response (curl)
$ curl -s http://localhost:3000/

match: enum দেখে view

Rust-এর সবচেয়ে প্রিয় জিনিস — match — এখানেও। প্রতিটা arm একটা view node; একাধিক হলে { } দিয়ে মুড়ে নিন।

💡 সব case না ঢাকলে compile error — তাই "এই status-এর view লিখতে ভুলে গেছি" ধরনের bug production-এ পৌঁছায় না।
Rust
use topcoat::{Result, router::{module_router, page}, view::{View, view}};

enum Payment { Cash, Bkash { number: &'static str }, Due(u32) }

#[tokio::main]
async fn main() {
    topcoat::start(module_router!().build()).await.unwrap();
}

#[page]
async fn home() -> Result<impl View> {
    let payments = vec![Payment::Cash, Payment::Bkash { number: "01711-000000" }, Payment::Due(5000)];
    Ok(view! {
        <ul>
            for p in payments {
                <li>
                    match p {
                        Payment::Cash => "নগদ",
                        Payment::Bkash { number } => <span>"bKash: " (number)</span>,
                        Payment::Due(amount) => <b>"বাকি " (amount) " Taka"</b>,
                    }
                </li>
            }
        </ul>
    })
}
Response (curl)
$ curl -s http://localhost:3000/
<ul><li>নগদ</li><li><span>bKash: 01711-000000</span></li><li><b>বাকি 5000 Taka</b></li></ul>

Component: নাম ধরে argument

Child: ভিতরে content

Component-এর ভিতরে যা লেখা হয় সেটা child হয়ে আসে। Parameter-এ #[default] child: Child<'_> রাখলে call-এ নাম ছাড়াই markup বসানো যায় — Blade-এর {{ $slot }}।

PHP/Laravel-এ যেমন <x-panel title="..."> ... </x-panel> আর ভিতরে {{ $slot }}।

use topcoat::{Result, router::{module_router, page}, view::{Child, View, component, view}};

async fn main() {

}

#[component]
async fn panel(title: &str, #[default] child: Child<'_>) -> Result<impl View> {

        </section>
    })
}

            <p>"Total: 23500 Taka"</p>

    })
}

Module routing: ফাইলই route

Laravel-এ routes/web.php-এ লিখতে হয়। Topcoat-এ module tree-ই route table: root module /, আর mod about; দিলে about.rs-এর page হয় /about। Function-এর নাম URL-এ কিছু করে না।

💡 আলাদা কোনো build step নেই — module_router!() macro compile-এর সময় module tree দেখে route বানায়।
ফোল্ডার
src/
├── main.rs          →  /        (mod about; mod posts;)
├── about.rs         →  /about
├── posts.rs         →  /posts
└── posts/
    └── post_id.rs   →  /posts/{post_id}

নিরাপত্তার জার্গন: XSS, CSRF, PRG

আগে দেখেছেন <script> text হয়ে গেল (escape); পরের lesson-এ আসছে POST-এর পর redirect — দুটোর পেছনেই একটা নিরাপত্তার ধারণা।

📘 জার্গন — শব্দের মানে
  • XSS (Cross-Site Scripting) — attacker-এর লেখা JavaScript আপনার page-এ ঢুকে অন্য user-দের browser-এ চলা; ( )-এর escape এটা আটকায়
  • CSRF (Cross-Site Request Forgery) — অন্য site-এর form/script আপনার login-করা user-কে দিয়ে চুপিসারে POST পাঠিয়ে দেওয়া; Topcoat default-এ cross-origin POST-কে 403 করে
  • PRG (Post/Redirect/Get) — POST-এর পর redirect (303) করে GET page দেখানো — refresh-এ form আবার submit হয় না
  • Escape — < কে &lt; বানানো যাতে text-টা HTML হিসেবে না চলে
  • Memoization — একই হিসাব একবার করে ফল মনে রাখা; Topcoat-এর #[memoize] প্রতি request-এ এটা করে
PHP/Laravel-এ যেমন Laravel-এ {{ }} escape করে (XSS) আর @csrf token ফেলে (CSRF)। Topcoat-এ প্রথমটা ( ) আর দ্বিতীয়টা origin policy।

Form আর redirect

Form<T> extractor form-এর data পড়ে। কাজ শেষে see_other(...) দিয়ে 303 redirect — যাতে browser refresh করলে form আবার submit না হয় (Post/Redirect/Get)। Laravel-এর redirect()->route('cart')।

💡 Browser থেকে আসা অন্য-site-এর POST (CSRF) Topcoat নিজেই 403 করে দেয় — default origin policy। curl-এ Origin header নেই, তাই এখানে চলেছে।
Rust
use serde::Deserialize;
use std::sync::Mutex;
use topcoat::{
    Result,
    context::{Cx, app_context},
    router::{
        RouterBuilderDiscoverExt, content::Form, error::see_other, href, module_router, page, route,
    },
    view::{View, view},
};

struct Cart(Mutex<Vec<String>>);

#[derive(Deserialize)]
struct AddItem {
    name: String,
}

#[tokio::main]
async fn main() {
    let router = module_router!().discover().app_context(Cart(Mutex::new(vec![]))).build();
    topcoat::start(router).await.unwrap();
}

#[page("/cart")]
async fn cart_page(cx: &Cx) -> Result<impl View> {
    let items = app_context::<Cart>(cx).0.lock().unwrap().clone();
    Ok(view! {
        <h1>"Cart (" (items.len()) ")"</h1>
        <ul>
            for item in items {
                <li>(item)</li>
            }
        </ul>
        <form method="post" action="/cart/add">
            <input name="name" placeholder="Product">
            <button>"যোগ করুন"</button>
        </form>
    })
}

#[route(POST "/cart/add")]
async fn add(cx: &Cx, Form(input): Form<AddItem>) -> Result<impl topcoat::router::response::IntoResponse> {
    app_context::<Cart>(cx).0.lock().unwrap().push(input.name);
    Ok(see_other(href!(cart_page).resolve(cx)))
}

Browser-এ code: $() runtime

Server-rendered page-এ click-এ কিছু বদলাতে চাই — কিন্তু WebAssembly ছাড়া। Topcoat-এর উত্তর: $( ... ) ভিতরের Rust expression server প্রথমবার চালায়, আর একই expression JavaScript-এ compile হয়ে browser-এও চলে।

  • $(...) — runtime expression
  • signal(cx, || 0) — browser-এর state
  • @click=$(...) — event handler
  • :hidden=$(...) — বদলে যাওয়া attribute
⚠️ Runtime এখনো highly experimental — সব Rust operation এখানে চলে না, শুধু একটা সীমিত অংশ। সীমার বাইরে গেলে compiler বলে দেয়।

Signal আর @click: Counter

signal(cx, || 0) একটা state, .get() দিয়ে পড়া, .set() দিয়ে লেখা। @click-এর মান একটা closure। Button চাপলে signal বদলায়, আর $(sold.get()) text নিজেই আবার আঁকে — সবটা browser-এই, server-এ না গিয়ে। তিনবার চাপার পর আসল screenshot:

PHP/Laravel-এ যেমন Alpine.js-এর x-data="{ sold: 0 }" আর @click="sold++"-এর মতো — কিন্তু লেখা হচ্ছে Rust-এ, type-checked।
Rust
use topcoat::{
    Result,
    asset::{AssetBundle, RouterBuilderAssetExt},
    context::Cx,
    router::{RouterBuilderDiscoverExt, module_router, page},
    runtime::{Event, RouterBuilderRuntimeExt, signal},
    view::{View, view},
};

#[tokio::main]
async fn main() {
    let router = module_router!()
        .discover()
        .assets(AssetBundle::load().unwrap())
        .runtime()
        .build();
    topcoat::start(router).await.unwrap();
}

#[page]
async fn home(cx: &Cx) -> Result<impl View> {
    let sold = signal(cx, || 0usize);
    Ok(view! {
        <!DOCTYPE html>

Procedure: browser থেকে server function

Click-এ database বা secret লাগলে #[procedure] — একটা async function যা server-এ চলে, কিন্তু runtime expression থেকে .await করে ডাকা যায়। ভিতরে Topcoat নিজেই HTTP request পাঠায়।

⚠️ Procedure একটা public HTTP endpoint — কেউ নিজে request পাঠিয়ে যেকোনো argument দিতে পারে। Argument validate আর authorization procedure-এর ভিতরেই করুন।

Shard: server থেকে আবার আঁকা অংশ

Search result-এর মতো server-এর data দিয়ে বানানো অংশ বদলাতে #[shard]: একটা component যার argument ($(query.get())) বদলালে server আবার HTML বানায়, আর browser শুধু সেই অংশ জায়গা-মতো বদলে দেয়। "redmi" লিখে দেখুন:

PHP/Laravel-এ যেমন Livewire-এর মূল কৌশলের কাছাকাছি: state বদলালে server HTML আবার বানায়। পার্থক্য — Topcoat শুধু ওই shard-টুকু আনে, আর state browser-এ signal-এ থাকে।
⚠️ Shard-এর নিজস্ব HTTP endpoint আছে; page-এর guard ওখানে চলে না। Argument validate আর authorization shard-এর ভিতরেই করুন।

use topcoat::runtime::shard;

const PRODUCTS: [&str; 4] = ["iPhone 15", "Samsung A55", "Redmi 13", "Redmi Note 13"];

#[shard]
async fn results(query: String) -> Result<impl View> {
    let q = query.to_lowercase();
    let found: Vec<&str> = PRODUCTS.iter().copied().filter(|p| p.to_lowercase().contains(&q)).collect();
    Ok(view! {
        <p>(found.len()) " টি পাওয়া গেছে"</p>
        <ul>
            for p in found {
                <li>(p)</li>
            }
        </ul>
    })
}

struct Product { id: u32, name: &'static str, price: u32 }
struct Catalog(Vec<Product>);

path_param!(id: u32, error = bad_request);

#[tokio::main]

        Product { id: 1, name: "iPhone 15", price: 112000 },

#[layout]
async fn shell(slot: Slot<'_>) -> Result<impl View> {

            </body>

#[page]
async fn home(cx: &Cx) -> Result<impl View> {

    Ok(view! {

#[page("/products/{id}")]
async fn product(cx: &Cx) -> Result<impl View> {
    let id = *path_param::<Id>(cx)?;
    let p = app_context::<Catalog>(cx).0.iter().find(|p| p.id == id).ok_or_not_found()?;

        <h1>(p.name)</h1>

    })
}

পাঠ ৪০

Quiz

❓ Topcoat-এ browser-এর interactivity WebAssembly দিয়ে হয় কি?

না। $(...)-এর ভিতরের Rust expression-এর একটা সীমিত অংশ JavaScript-এ compile হয়। সেটাই Leptos থেকে বড় পার্থক্য — Leptos Rust-কে wasm বানায়।

❓ #[shard] আর #[procedure]-এর পার্থক্য কী?

Procedure একটা server function — browser ডেটা চায়, JavaScript সেই ডেটা নিয়ে যা খুশি করে। Shard একটা component — argument বদলালে server আবার HTML বানায়, আর browser সেই অংশ বদলে দেয়।

❓ Layout আর Slot-এর কাজ কী?

Layout ভিতরের page-টা Slot হিসেবে পায় এবং নিজের markup-এর মাঝখানে বসায় — যেমন Blade-এর @extends আর @yield।
