Rust Leptos
Reactive Full-stack Web

Livewire আর Vue/React যা করে — interactive UI — সেটাই পুরোপুরি Rust-এ। Virtual DOM ছাড়া, fine-grained reactivity দিয়ে। প্রতিটি উদাহরণ আসলেই browser-এ চালানো, screenshot আসল।

  • Leptos কী, আর Virtual DOM ছাড়া কীভাবে চলে
  • view! macro আর component
  • Signal, Memo, Effect — reactivity
  • Event, form আর list (For, Show)
  • Context আর shared state
  • Resource আর Suspense (async data)
  • Router: একাধিক page
  • SSR, server function আর hydration

আগে জানা দরকার: Rust 101–103 (struct, closure, trait, Option/Result)। Rust Web Development পড়া থাকলে SSR অংশ সহজ লাগবে।

পাঠ ১

Leptos কী?

Leptos হলো Rust-ভিত্তিক full-stack web framework। একই Rust code browser-এ (client-side rendering), server-এ (SSR) আর server-এর HTML-কে জীবন্ত করতে (hydration) চলে।

  • Fine-grained reactivity — যে value বদলাল, শুধু সেই text/attribute বদলায়
  • Virtual DOM নেই — React-এর মতো পুরো tree তুলনা করা হয় না
  • Component function একবারই চলে, তারপর signal DOM আপডেট করে
  • Compile হয় WebAssembly-তে, তাই browser-এ Rust চলে
PHP/Laravel-এ যেমন Livewire-এ button চাপলে server-এ round trip হয়ে HTML ফেরত আসে। Leptos-এ (CSR) logic browser-এই চলে, server-কে ডাকতে হয় শুধু data লাগলে।

প্রথম Hello, World! — server-এ render

সবচেয়ে ছোট Leptos program। এখানে browser নেই — to_html() view-কে সরাসরি HTML string বানায়, ঠিক SSR যা করে।

💡 view!-এর ভিতরে text সবসময় quote-এ ("...") লিখতে হয়। এটা Rust-এর নিয়ম, HTML-এর না।
Rust
use leptos::prelude::*;

#[component]
fn Hello() -> impl IntoView {
    view! { <h1>"Hello, World!"</h1> }
}

fn main() {
    println!("{}", view! { <Hello/> }.to_html());
}

পাঠ ৬

view! — Rust-এর ভিতরে HTML

view! HTML-এর মতো লেখা যায়, কিন্তু এটা type-checked Rust। ভুল tag বা ভুল attribute হলে compile-ই হবে না।

PHP/Laravel-এ যেমন Blade-এ <div class="card"> সরাসরি লিখি। এখানেও প্রায় তাই — শুধু text-এ quote আর self-closing tag-এ /।
Rust
use leptos::prelude::*;

fn main() {
    let view = view! {
        <div class="card" id="p1">
            <h2>"iPhone 15"</h2>
            <p style="color: green">"In stock"</p>
            <a href="/products/1">"Details"</a>
        </div>
    };
    println!("{}", view.to_html());
}
আউটপুট
<div id="p1" class="card"><h2>iPhone 15</h2><p style="color: green">In stock</p><a href="/products/1">Details</a></div>

Text-এ value বসানো

{...}-এর ভিতরে যেকোনো Rust expression বসানো যায় — Blade-এর {{ $x }}-এর মতো।

💡 আউটপুটের <!> হলো hydration-এর জন্য ছোট marker comment — পরে hydration lesson-এ কাজে লাগবে। Browser-এ এগুলো কিছু দেখায় না।
Rust
use leptos::prelude::*;

fn main() {
    let name = "Samsung A55";
    let price = 41500;
    let view = view! {
        <p>{name} " — " {price} " Taka"</p>
        <p>"VAT সহ: " {price * 115 / 100}</p>
    };
    println!("{}", view.to_html());
}

Component: ছোট function, বড় কাজ

#[component] দেওয়া function-ই একটা component। নাম বড় হাতের অক্ষরে শুরু (ProductCard), আর view-তে <ProductCard/> লিখে ব্যবহার।

PHP/Laravel-এ যেমন Blade-এ <x-product-card /> — ঠিক একই ধারণা, শুধু class-এর বদলে function।
Rust
use leptos::prelude::*;

#[component]
fn ProductCard() -> impl IntoView {
    view! {
        <div class="card">
            <h2>"iPhone 15"</h2>
            <p>"Price: 112000 Taka"</p>
        </div>
    }
}

fn main() {
    let page = view! {
        <ProductCard/>
        <ProductCard/>
    };
    println!("{}", page.to_html());
}

Props: component-কে data দেওয়া

Component function-এর argument-ই তার props। view-তে লেখা হয় HTML attribute-এর মতো: name="..."।

PHP/Laravel-এ যেমন Blade-এ @props(['name', 'price'])। Rust-এ type দিতে হয় — ভুল type দিলে compile error।
Rust
use leptos::prelude::*;

fn ProductCard(name: &'static str, price: u32) -> impl IntoView {

        </div>

}

fn main() {
    let page = view! {
        <ProductCard name="iPhone 15" price=112000/>
        <ProductCard name="Redmi 13" price=18500/>

    println!("{}", page.to_html());

Optional আর default prop

সব prop বাধ্যতামূলক নয়। #[prop(optional)] দিলে না দিলে Option বা default; #[prop(into)] দিলে &str থেকে String নিজে হয়ে যায়।

PHP/Laravel-এ যেমন @props(['branch' => 'Mirpur'])-এর মতো default value।
Rust
use leptos::prelude::*;

#[component]
fn ProductCard(
    #[prop(into)] name: String,
    price: u32,
    #[prop(optional)] discount: u32,
    #[prop(default = "Mirpur")] branch: &'static str,
) -> impl IntoView {
    view! { <p>{name} ": " {price - discount} " Taka (" {branch} ")"</p> }
}

fn main() {
    let page = view! {
        <ProductCard name="Redmi 13" price=18500/>
        <ProductCard name="Redmi 13" price=18500 discount=1500 branch="Uttara"/>
    };
    println!("{}", page.to_html());
}
আউটপুট

Children: ভিতরে content বসানো

Component-এর ভিতরে যা লেখা হয়, সেটা children: Children হয়ে আসে। Blade-এর {{ $slot }}-এর মতো।

PHP/Laravel-এ যেমন Blade: <x-card title="..."> ... </x-card> আর card-এর ভিতরে {{ $slot }}।
Rust
use leptos::prelude::*;

#[component]
fn Card(#[prop(into)] title: String, children: Children) -> impl IntoView {
    view! {
        <section class="card">
            <h3>{title}</h3>
            {children()}
        </section>
    }
}

fn main() {
    let page = view! {
        <Card title="Invoice INV-1001">
            <p>"Customer: Karim"</p>
            <p>"Total: 23500 Taka"</p>
        </Card>
    };
    println!("{}", page.to_html());
}

Signal: বদলাতে পারে এমন value

signal(0) দুটো জিনিস দেয়: পড়ার handle (get) আর লেখার handle (set/update)। এটাই Leptos-এর হৃদয়।

PHP/Laravel-এ যেমন Vue-এর const stock = ref(10)-এ read/write একই object-এ। Leptos-এ read আর write আলাদা — কে বদলাতে পারবে সেটা নিয়ন্ত্রণে রাখা যায়।
Rust
use leptos::prelude::*;

fn main() {
    let (stock, set_stock) = signal(10);
    println!("শুরুতে: {}", stock.get());

    set_stock.set(8);
    println!("set(8) এর পর: {}", stock.get());

    set_stock.update(|n| *n -= 3);
    println!("update(-3) এর পর: {}", stock.get());
}
আউটপুট
শুরুতে: 10
set(8) এর পর: 8
update(-3) এর পর: 5

প্রথম interactive component: Counter

Signal-কে view-তে বসাতে {stock} লিখলেই হয়। on:click-এ signal বদলালে শুধু ওই text বদলায়। নিচে button তিনবার চাপা হয়েছে — আসল browser-এ।

💡 Event handler move |_| ... closure — move দিয়ে signal-এর handle closure-এ নিয়ে নেওয়া হয়। Signal Copy হওয়ায় clone করতে হয় না।
Rust
use leptos::prelude::*;

#[component]
fn App() -> impl IntoView {
    let (sold, set_sold) = signal(0);

    view! {
        <button on:click=move |_| set_sold.update(|n| *n += 1)>
            "বিক্রি হলো"
        </button>
        <p>"আজ বিক্রি: " {sold} " টি"</p>
    }
}

fn main() {
    leptos::mount::mount_to_body(App);
}

Component function একবারই চলে

React-এ state বদলালে পুরো component আবার চলে। Leptos-এ component শুধু একবার চলে — view বানায়। এরপর signal সরাসরি ওই text node-টাকে বদলায়। প্রমাণ নিচে:

পাঁচ click-এও body চলেছে ১ বার — Virtual DOM diff-এর দরকারই পড়েনি।

Rust
use leptos::prelude::*;

#[component]
fn App() -> impl IntoView {
    let runs = StoredValue::new(0);
    runs.update_value(|n| *n += 1);   // component body-তে — কয়বার চলল গুনছি
    let (clicks, set_clicks) = signal(0);

    view! {
        <button on:click=move |_| set_clicks.update(|n| *n += 1)>"Click"</button>
        <p>"Component body চলেছে: " {runs.get_value()} " বার"</p>
        <p>"Click হয়েছে: " {clicks} " বার"</p>
    }
}

fn main() {
    leptos::mount::mount_to_body(App);
}

Derived signal: signal থেকে হিসাব

Signal-এর উপর নির্ভর করা হিসাব লিখতে সাধারণ closure-ই যথেষ্ট: move || price.get() * qty.get()। View-তে বসালে signal বদলালেই নতুন হিসাব।

PHP/Laravel-এ যেমন Vue-এর computed(() => price * qty.value)। Livewire-এ #[Computed] property।
Rust
use leptos::prelude::*;

#[component]
fn App() -> impl IntoView {
    let (qty, set_qty) = signal(1);
    let price = 18500;
    let total = move || price * qty.get();

    view! {
        <button on:click=move |_| set_qty.update(|q| *q += 1)>"+"</button>
        <button on:click=move |_| set_qty.update(|q| *q = (*q - 1).max(1))>"−"</button>
        <p>"Redmi 13 × " {qty}</p>
        <p class="bold">"Total: " {total} " Taka"</p>
    }
}

fn main() {
    leptos::mount::mount_to_body(App);
}

Memo: দামী হিসাব একবারই

Derived closure প্রতিবার পড়ার সময় আবার চলে। হিসাব ভারী হলে Memo ব্যবহার করুন — dependency বদলালে তবেই নতুন করে হিসাব, নইলে আগের ফল।

💡 Memo শুধু ততক্ষণই নতুন করে চলে যতক্ষণ সে যে signal পড়ে তার কোনোটা বদলায়। উপরে note বদলালে হিসাব চলেনি।
Rust
use leptos::prelude::*;

fn main() {
    let (qty, set_qty) = signal(2);
    let (note, set_note) = signal("cash");

    let total = Memo::new(move |_| {
        println!("  (হিসাব চলছে)");
        18500 * qty.get()
    });

    println!("১ম পড়া: {}", total.get());
    println!("২য় পড়া: {}", total.get());
    set_note.set("bkash");               // qty বদলায়নি
    println!("note বদলানোর পর: {} ({})", total.get(), note.get());
    set_qty.set(3);
    println!("qty বদলানোর পর: {}", total.get());
}

Effect: signal বদলালে side effect

Effect একটা কাজ চালায় (log, localStorage, API call) আর সে যে signal পড়ে সেগুলো বদলালেই আবার চলে। এখানে আমরা terminal-এ চালাচ্ছি বলে async executor (tokio) আর effects feature চালু করা হয়েছে।

PHP/Laravel-এ যেমন Vue-এর watchEffect() বা watch()। Laravel-এ কাছাকাছি হলো model observer/event listener।
💡 Server-এ (SSR) Effect চলে না — শুধু browser-এ। তাই DOM বা localStorage ছোঁয়া code Effect-এর ভিতরে রাখুন, component body-তে নয়।
⚠️ Effect দিয়ে অন্য signal সেট করে হিসাব বানাবেন না — সেটার জন্য derived signal বা Memo। Effect শুধু বাইরের জগতের (DOM, log, storage) জন্য।
Rust
use any_spawner::Executor;
use leptos::prelude::*;
use reactive_graph::effect::Effect;
use std::time::Duration;

#[tokio::main]
async fn main() {
    tokio::task::LocalSet::new().run_until(run()).await;
}

async fn run() {
    Executor::init_tokio().unwrap();
    let owner = Owner::new();
    owner.set();

    let (stock, set_stock) = signal(10);
    Effect::new(move |_| {
        println!("stock এখন {}", stock.get());
    });

    tokio::time::sleep(Duration::from_millis(50)).await;
    set_stock.set(7);
    tokio::time::sleep(Duration::from_millis(50)).await;
    set_stock.set(4);
    tokio::time::sleep(Duration::from_millis(50)).await;
}

stock এখন 10

Dynamic class আর style

class:নাম=... একটা condition true হলে class যোগ করে। শুধু ওই attribute বদলায়, পুরো element নয়। Stock ৫-এর নিচে নামলে লাল হয়ে যাবে।

⚠️ view!-এর attribute-এর ভিতরে সরাসরি < বা > লিখলে macro সেটাকে tag-এর অংশ ভাবে। তুলনা আলাদা closure-এ রাখুন (let low = move || stock.get() < 5;) — code-ও পরিষ্কার থাকে।
PHP/Laravel-এ যেমন Blade-এ @class(['low' => $stock < 5])। Vue-এ :class="{ low: stock < 5 }"।
Rust
use leptos::prelude::*;

#[component]
fn App() -> impl IntoView {
    let (stock, set_stock) = signal(7);
    let low = move || stock.get() < 5;

    view! {
        <button on:click=move |_| set_stock.update(|n| *n -= 1)>"১টা বিক্রি"</button>
        <p class:low=low class:ok=move || !low()>
            "Redmi 13 stock: " {stock}
        </p>
        <p style:font-size=move || format!("{}px", 12 + stock.get())>"stock যত কমে, লেখা তত ছোট"</p>
    }
}

fn main() {
    leptos::mount::mount_to_body(App);
}

Input আর two-way binding

PHP/Laravel-এ যেমন Vue-এর v-model বা Livewire-এর wire:model এই দুই লাইনের shortcut। Leptos-এ shortcut নেই; ফলে কী হচ্ছে সবসময় চোখের সামনে।

use leptos::prelude::*;

#[component]
fn App() -> impl IntoView {
    let (name, set_name) = signal(String::new());

    view! {
        <input type="text" placeholder="গ্রাহকের নাম"
            prop:value=name
            on:input:target=move |ev| set_name.set(ev.target().value())
        />
        <p>"Invoice: " {move || if name.get().is_empty() { "—".to_string() } else { format!("{} -এর জন্য", name.get()) }}</p>
    }
}

fn main() {
    leptos::mount::mount_to_body(App);

For: list দেখানো

<For>-এ তিনটে জিনিস: each (list), key (প্রতিটার unique id), children (প্রতিটা কেমন দেখাবে)। key থাকায় Leptos জানে কোন row যোগ/বাদ হলো — বাকিগুলো ছোঁয় না।

PHP/Laravel-এ যেমন @foreach ($products as $p)। বাড়তি key লাগে যাতে list বদলালে শুধু বদলানো row-টাই DOM-এ আপডেট হয়।
Rust
use leptos::prelude::*;

#[derive(Clone)]
struct Product { id: u32, name: &'static str, price: u32 }

#[component]
fn App() -> impl IntoView {
    let (products, _) = signal(vec![
        Product { id: 1, name: "iPhone 15", price: 112000 },
        Product { id: 2, name: "Samsung A55", price: 41500 },
        Product { id: 3, name: "Redmi 13", price: 18500 },
    ]);

    view! {
        <ul>
            <For
                each=move || products.get()
                key=|p| p.id
                children=|p| view! { <li>{p.name} " — " {p.price} " Taka"</li> }
            />
        </ul>
    }
}

fn main() {
    leptos::mount::mount_to_body(App);
}

List-এ যোগ আর বাদ

Cart বানাই: Vec-টা একটা signal। update-এ push/retain করলেই list নিজে আপডেট হয়।

Rust
use leptos::prelude::*;

#[derive(Clone)]
struct Item { id: u32, name: &'static str, price: u32 }

#[component]
fn App() -> impl IntoView {
    let (cart, set_cart) = signal(Vec::<Item>::new());
    let (next_id, set_next_id) = signal(1u32);

    let add = move |name: &'static str, price: u32| {
        set_cart.update(|c| c.push(Item { id: next_id.get(), name, price }));
        set_next_id.update(|n| *n += 1);
    };
    let total = move || cart.get().iter().map(|i| i.price).sum::<u32>();

    view! {
        <button on:click=move |_| add("Redmi 13", 18500)>"Redmi 13"</button>
        <button on:click=move |_| add("Charger", 1200)>"Charger"</button>
        <ul>
            <For
                each=move || cart.get()
                key=|i| i.id
                children=move |i| {
                    let id = i.id;
                    view! {
                        <li>
                            {i.name} " — " {i.price} " "
                            <button on:click=move |_| set_cart.update(|c| c.retain(|x| x.id != id))>"✕"</button>
                        </li>
                    }
                }
            />
        </ul>
        <p class="total">"মোট: " {total} " Taka"</p>
    }
}

fn main() {
    leptos::mount::mount_to_body(App);
}

API থেকে data আনা: LocalResource

Browser-এ server থেকে data আনতে LocalResource — একটা async block দিন, ফল আসা পর্যন্ত Leptos অপেক্ষা করে। <Suspense> বলে অপেক্ষার সময় কী দেখাবে। এখানে আসলেই /products.json request যাচ্ছে।

PHP/Laravel-এ যেমন Vue-এ onMounted(() => fetch(...)) আর v-if="loading" হাতে লিখতে হয়। এখানে Resource + Suspense সেটা একসাথে সামলায়।
Rust
use gloo_net::http::Request;
use gloo_timers::future::TimeoutFuture;
use leptos::prelude::*;
use serde::Deserialize;

#[derive(Clone, Deserialize)]
struct Product { name: String, price: u32, stock: u32 }

async fn load_products() -> Vec<Product> {
    TimeoutFuture::new(1500).await;   // ধীর network বোঝাতে
    Request::get("/products.json").send().await.unwrap().json().await.unwrap()
}

#[component]
fn App() -> impl IntoView {
    let products = LocalResource::new(load_products);

    view! {
        <h3>"Rahim Mobile"</h3>
        <Suspense fallback=|| view! { <p class="muted">"লোড হচ্ছে…"</p> }>
            {move || Suspend::new(async move {
                let list = products.await;
                view! {
                    <ul>
                        {list.into_iter().map(|p| view! { <li>{p.name} " — " {p.price} " Taka (" {p.stock} ")"</li> }).collect_view()}
                    </ul>
                }
            })}
        </Suspense>
    }
}

fn main() {
    leptos::mount::mount_to_body(App);
}

Resource আবার চালানো

Resource-এর async block যে signal পড়ে, সেটা বদলালে সে নিজে নতুন করে data আনে। Branch বদলালে stock আবার আসছে — হাতে কিছু লিখতে হয়নি।

Rust
use gloo_net::http::Request;
use gloo_timers::future::TimeoutFuture;
use leptos::prelude::*;
use serde::Deserialize;

#[derive(Clone, Deserialize)]
struct Product { name: String, stock: u32 }

#[component]
fn App() -> impl IntoView {
    let (min_stock, set_min_stock) = signal(0u32);

    let products = LocalResource::new(move || {
        let min = min_stock.get();
        async move {
            TimeoutFuture::new(200).await;
            let all: Vec<Product> = Request::get("/products.json").send().await.unwrap().json().await.unwrap();
            all.into_iter().filter(|p| p.stock >= min).collect::<Vec<_>>()
        }
    });

    view! {
        <button on:click=move |_| set_min_stock.set(5)>"স্টক ≥ ৫ দেখান"</button>
        <Suspense fallback=|| view! { <p class="muted">"লোড হচ্ছে…"</p> }>
            {move || Suspend::new(async move {
                let list = products.await;
                view! { <ul>{list.into_iter().map(|p| view! { <li>{p.name} " (" {p.stock} ")"</li> }).collect_view()}</ul> }
            })}
        </Suspense>
    }
}

fn main() {
    leptos::mount::mount_to_body(App);
}

Route parameter

path!("/products/:id") — Laravel-এর /products/{id}। Component-এর ভিতরে use_params_map() দিয়ে মান পড়া যায়।

💡 Parameter বদলালে (/products/1 → /products/2) component আবার তৈরি হয় না — params signal বদলায়, তাই শুধু ওই text আপডেট হয়।
Rust
use leptos::prelude::*;
use leptos_router::components::{Route, Router, Routes, A};
use leptos_router::hooks::use_params_map;
use leptos_router::path;

#[component]
fn List() -> impl IntoView {

        <ul>
            <li><A href="/products/1">"iPhone 15"</A></li>
            <li><A href="/products/2">"Samsung A55"</A></li>
        </ul>
    }
}

#[component]
fn Detail() -> impl IntoView {
    let params = use_params_map();
    let id = move || params.read().get("id").unwrap_or_default();

        <h3>"Product #" {id}</h3>
        <A href="/">"← সব product"</A>
    }
}

#[component]
fn App() -> impl IntoView {
    view! {
        <Router>
            <Routes fallback=|| "404">
                <Route path=path!("/") view=List/>
                <Route path=path!("/products/:id") view=Detail/>
            </Routes>
        </Router>
    }
}

fn main() {
    leptos::mount::mount_to_body(App);
}

Server: axum আর shell

Server হলো সাধারণ axum app (Rust Web Development-এর মতোই)। shell হলো পুরো HTML page; HydrationScripts সঠিক <script> বসায়; leptos_routes আপনার App render করে।

src/main.rs
use app::App;
use axum::Router;
use leptos::prelude::*;
use leptos_axum::{LeptosRoutes, generate_route_list};

fn shell(options: LeptosOptions) -> impl IntoView {
    view! {
        <!DOCTYPE html>
        <html lang="bn">
            <head>
                <meta charset="utf-8"/>
                <HydrationScripts options/>
            </head>
            <body><App/></body>
        </html>
    }
}

#[tokio::main]
async fn main() {
    let options = LeptosOptions::builder()
        .output_name("app")
        .site_root("site")
        .site_addr("127.0.0.1:3000".parse::<std::net::SocketAddr>().unwrap())
        .build();
    let routes = generate_route_list(App);
    let app = Router::new()
        .leptos_routes(&options, routes, {
            let options = options.clone();
            move || shell(options.clone())
        })
        .fallback(leptos_axum::file_and_error_handler(shell))
        .with_state(options.clone());
    let listener = tokio::net::TcpListener::bind(options.site_addr).await.unwrap();
    axum::serve(listener, app).await.unwrap();
}

Server function: browser থেকে server-এর Rust function

#[server] দিলে function-টা শুধু server-এ চলে। Browser-এ সেটার জায়গায় একটা stub বসে, যে নিজে HTTP request পাঠায়। আলাদা API route, controller, fetch কিছু লিখতে হয় না।

PHP/Laravel-এ যেমন Laravel-এ Route::post('/api/stock') + controller + browser-এ fetch('/api/stock') — তিনটা জিনিস। Leptos-এ একটাই function, type-checked দুই দিকেই।
⚠️ Server function public HTTP endpoint — Laravel-এর মতোই এখানেও authentication/validation আপনার দায়িত্ব।
src/lib.rs
use leptos::prelude::*;

#[server(endpoint = "stock")]
pub async fn stock_of(id: u32) -> Result<u32, ServerFnError> {
    // এখানে database query-ও চলতে পারত — এই code browser-এ কখনো পৌঁছায় না
    Ok(match id {
        1 => 4,
        2 => 9,
        _ => 2,
    })
}

#[component]
pub fn App() -> impl IntoView {
    let check = Action::new(|id: &u32| stock_of(*id));
    view! {
        <button on:click=move |_| { check.dispatch(2); }>"Samsung A55-এর stock দেখুন"</button>
        <p>"Stock: " {move || check.value().get().map(|r| format!("{:?}", r))}</p>
    }
}

#[cfg(feature = "hydrate")]
#[wasm_bindgen::prelude::wasm_bindgen]
pub fn hydrate() {
    leptos::mount::hydrate_body(App);
}

Server data আগেই HTML-এ

Resource + server function + Suspense-এ server নিজেই data আনে। Route-এ ssr=SsrMode::Async দিলে server সব data আসা পর্যন্ত অপেক্ষা করে, তারপর পুরো HTML একবারে পাঠায়। User "লোড হচ্ছে…" দেখে না, আর search engine পুরো list পায়।

উপরের curl-এ <li>গুলো দেখুন — JavaScript ছাড়াই data HTML-এ আছে।

💡 ডিফল্ট mode-এ Leptos আগে fallback ("লোড হচ্ছে…") পাঠায়, data পরে একই response-এ stream করে — page দ্রুত খোলে। SEO বা পুরো HTML দরকার হলে SsrMode::Async।
src/lib.rs
use leptos::prelude::*;
use leptos_router::components::{Route, Router, Routes};
use leptos_router::{SsrMode, path};

#[server(endpoint = "products")]
pub async fn products() -> Result<Vec<(String, u32)>, ServerFnError> {
    Ok(vec![
        ("iPhone 15".to_string(), 112000),
        ("Samsung A55".to_string(), 41500),
        ("Redmi 13".to_string(), 18500),
    ])
}

#[component]
fn Home() -> impl IntoView {
    let list = Resource::new(|| (), |_| products());
    view! {
        <h3>"Rahim Mobile"</h3>
        <Suspense fallback=|| view! { <p>"লোড হচ্ছে…"</p> }>
            {move || Suspend::new(async move {
                let items = list.await.unwrap_or_default();
                view! {
                    <ul>
                        {items.into_iter().map(|(n, p)| view! { <li>{n} " — " {p} " Taka"</li> }).collect_view()}
                    </ul>
                }
            })}
        </Suspense>
    }
}

#[component]
pub fn App() -> impl IntoView {
    view! {
        <Router>
            <Routes fallback=|| "404">
                <Route path=path!("/") view=Home ssr=SsrMode::Async/>
            </Routes>
        </Router>
    }
}

#[cfg(feature = "hydrate")]
#[wasm_bindgen::prelude::wasm_bindgen]
pub fn hydrate() {
    leptos::mount::hydrate_body(App);
}

Mini project: Rahim Mobile POS

এ পর্যন্ত যা শিখলাম — signal, Memo, For, Show, component, callback — সব একসাথে। Product-এ চাপলে cart-এ যায়, stock কমে, মোট হিসাব নিজে হয়, stock শেষ হলে button বন্ধ।

নিজে করুন Cart-এর প্রতিটা item-এর পাশে "✕" button যোগ করুন, যা item বাদ দিয়ে stock আবার ফেরত দেয়। (ইঙ্গিত: For আর retain)
Rust
use leptos::prelude::*;

#[derive(Clone, Copy)]
struct Phone { name: &'static str, price: u32 }

const PHONES: [Phone; 3] = [
    Phone { name: "iPhone 15", price: 112000 },
    Phone { name: "Samsung A55", price: 41500 },
    Phone { name: "Redmi 13", price: 18500 },
];

#[component]
fn Row(phone: Phone, stock: RwSignal<u32>, #[prop(into)] on_add: Callback<Phone>) -> impl IntoView {
    let empty = move || stock.get() == 0;
    view! {
        <div class="card">
            <span class="bold">{phone.name}</span>" — " {phone.price} " Taka"
            <p class:low=empty class:muted=move || !empty()>"স্টক: " {stock}</p>
            <button disabled=empty on:click=move |_| on_add.run(phone)>"Cart-এ দিন"</button>
        </div>
    }
}

#[component]
fn App() -> impl IntoView {
    let stocks: Vec<RwSignal<u32>> = vec![RwSignal::new(1), RwSignal::new(5), RwSignal::new(2)];
    let (cart, set_cart) = signal(Vec::<Phone>::new());
    let total = Memo::new(move |_| cart.get().iter().map(|p| p.price).sum::<u32>());

    let rows = PHONES.iter().zip(stocks.clone()).map(|(p, stock)| {
        view! {
            <Row phone=*p stock=stock on_add=move |p: Phone| {
                stock.update(|s| *s -= 1);
                set_cart.update(|c| c.push(p));
            }/>
        }
    }).collect_view();

    view! {
        <h3>"Rahim Mobile"</h3>
        {rows}
        <p class="total">"Cart: " {move || cart.get().len()} " টি · মোট " {total} " Taka"</p>
    }
}

fn main() {
    leptos::mount::mount_to_body(App);
}

Quiz

❓ Signal বদলালে Leptos-এ component function আবার চলে কি?

না। Component function শুধু একবার চলে। Signal বদলালে শুধু সেই text/attribute (যে signal পড়ছে) আপডেট হয় — Virtual DOM diff লাগে না।

❓ <For>-এ key কেন লাগে?

যাতে list বদলালে Leptos বোঝে কোন item যোগ/বাদ/সরল — শুধু সেই row DOM-এ বদলায়, বাকিগুলো যেমন আছে তেমনই থাকে।

❓ Hydration আর CSR-এর পার্থক্য কী?

CSR-এ browser খালি page থেকে শুরু করে DOM বানায়। Hydration-এ server আগেই HTML পাঠিয়েছে; wasm এসে সেই DOM-এই event আর signal জুড়ে দেয় — নতুন করে বানায় না।
